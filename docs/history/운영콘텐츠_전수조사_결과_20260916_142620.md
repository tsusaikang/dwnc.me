## 2. 최신 자료·조사 범위

- 9월 15일 시작한 실행은 중간에 끊겼으며 9월 16일 재개했다. 이전 6개 글·7개 카드 조사를 운영 전체 결과로 재사용하지 않았다.
- 9월 16일 14:11경 운영 `search-index.json` 전체 350편을 새로 조회했다. 9월 15일 이번 작업의 최초 조회와 비교해 추가·삭제·목록 데이터 변경은 없었다.
- 9월 16일 14:14~14:17경 내장 브라우저의 인증된 Cloudflare D1 Console에서 SELECT만 사용해 `native_posts` 2편·`legacy_posts` 596편의 최신 제목·요약·본문·대표이미지·상태·revision을 읽었다. 전체 묶음 조회는 크기 오류로 실패해 50편씩 나눠 받았다.
- 최신 DB의 **598편은 공개 350편·비공개 248편**이다. 모두 글 유형이며 import 완료 상태다. 관리자의 전체 수와 일치하고 현재 공개 350편 모두 DB에 존재한다. 현재 목록에 정적 대체 글이 섞여 발생한 오류는 발견하지 않았다.
- `editor_working_copies` 3개는 별도로 읽었다. 공개 글 2개·비공개 글 1개이며 제목·요약·본문·대표이미지에 반영본과 차이가 없고 revision도 반영 revision과 같다. 작업본 행의 존재와 공개하지 않은 내용 차이를 구분했다.
- 마감 전 전체 ID·revision·수정시각·공개 상태를 다시 읽어 598편 모두 최초 DB 수집과 같음을 확인했다. 분할 조회이며 조회 후의 사용자 변경까지 보장하지 않는다.
- 네이버·티스토리 이관 덤프와 `src/data/posts`는 조사 입력으로 사용하지 않았다. 현재 소스·미디어 계약·허용목록은 표시 원인을 해석하는 용도로만 읽었다.
- 주요 분석은 링크·대표이미지·카드 담당 하위 에이전트에 나눴다. 메인은 기존 로그인 세션으로 운영 DB/API 접근, 내장 브라우저 표시 확인, 결과 통합·공식 기록을 담당했다. 추가 권한·인증키를 만들지 않았다.

## 3. 내부·외부 링크 표시

공개 350편의 본문 링크 411개를 대조했다. 내부 글 링크 75개(40편)는 모두 현재 공개 글의 `/posts/N` 주소를 가리키며, 이 중 카드가 45개다. 외부 목적지 링크는 336개다. 외부 일반 링크 전체의 생존 여부를 점검하는 별도 링크 크롤링은 범위에 넣지 않았고, 카드의 외부 목적지는 아래처럼 조회했다.

이번 DB 전수 분석에서 저장된 ‘외부 링크’ 문구가 다시 발견된 대상은 590→589, 582→581, 563→525, 555→543, 551→550, 462→452·453이다. 최신 HTTP 본문 4개와 내장 브라우저의 나머지 3개를 합쳐 **7개 모두 실제로 ‘블로그 글’ 표시**를 확인했다. 저장 데이터에 남은 옛 문구와 현재 이용자에게 보이는 오류는 다르다. 현재 표시 보완은 제목·요약을 대상 데이터로 갱신하는 기능은 아니다.

내부 네이버 카드의 옛 도메인 표시는 별도 후보다. 대상 글은 80, 176, 188, 221, 226, 231, 238, 260, 261, 268, 272, 280, 284, 285, 286, 288, 291, 326, 332번이며 총 26카드다. 285번의 두 카드는 실제 화면에서도 내부 주소와 `blog.naver.com`·‘이미지 보존 대기’ 문구가 함께 보였다. 다른 24카드는 저장본문 근거이며 각각 육안 확인한 것은 아니다.
