# 사진 정보의 PC 가독성과 모바일 상시 표시

## 요청과 완료조건

2026-10-05 사용자가 무배경 사진 정보의 줄간격·정렬, 요약/상세 중복, 작은 글씨를 지적했다. PC는 글씨를 키우고 정돈하며 모바일은 간단/상세 구분을 없애고 항목별 세로줄 대신 정보 내용을 `/`로 이어 화면 상단에 항상 표시하도록 요청했다. 기존 CORE-041의 승인된 후속이며 `84833a8`·미커밋 없음에서 시작했다. 실제 글·사진·작업본 변경, 공개 전환, 권한 변경은 없다.

모바일 위치는 상단 고정과 사진별 위쪽을 질문했다. 답변 전까지 현재 보는 사진 정보를 화면 상단에 고정하는 기본안으로 준비한다. PC는 요약14px·상세14px, 제목15~16px·보조문구12px, 항목명/값 같은 줄·일관된 오른쪽 끝으로 정리한다. 상세를 펼치면 요약과 그 빈44px 공간을 숨겨 해상도/용량을 상세에서만 한 번 표시한다. 배경 없이 짙은 글자 그림자는 유지한다.

모바일767px 이하는 헤더 아래 상단 한 영역에서 현재 보이는 사진만 표시한다. 편집에서 선택사진이 보이면 그 사진, 아니면 화면 상단에 가까운 사진을 사용한다. 사진번호·해상도·용량·형식·색영역·프로필·HDR 상태를 슬래시로 이어 표시하고 길면 자연스럽게 줄바꿈한다. 모르는 정보는 단정하지 않으며 HDR 메타데이터와 실제 HDR 지원/SDR 여부를 구분한다. 내용과 클릭을 가로채지 않는다. 사진이 보이지 않으면 이전 사진 정보를 숨긴다.

현재 사진만 기존 제한된 상세 API로 자동 조회하고 캐시/진행 중 요청을 재사용한다. 사진·글·화면폭 전환 뒤 오래된 응답을 막고, 실패한 조회를 스크롤마다 반복하지 않는다. PC 관련 동작, 사진 선택·설명·이동·undo·본문/작업본 저장은 유지한다. 관련·전체 편집기 회귀·독립 검토·PC/모바일 자체 브라우저·최종 소스 빌드·기존 Git 반영·양쪽 운영 읽기 확인이 완료조건이다.

## 역할과 이번 조회

하위 `public_info_layout`은 공개 스크립트/CSS/관련 검사, `editor_info_layout`은 편집 스크립트/CSS/관련 검사, `mobile_info_review`는 독립 읽기 검토를 맡는다. 메인은 조정·통합·브라우저·최종 검사·공식 상태·Git을 맡는다. 브라우저는 메인 사용자 세션에 연결돼 요청한 동작만 직접 확인한다.

이번 최신 공개 #600은9사진·총8.26MB, 편집 #605는4사진·공개와 같은 작업본·마지막 저장2026-09-30 21:24:44 KST로 읽었다. 첨부와 같은 공개 사진3의 해상도1928×2560·579,404바이트·JPEG·Display P3·실제 ICC명·HDR 메타데이터도 운영 API 응답으로 다시 확인했다. 조회 후 사용자의 변경 가능성은 유지하며 과거 이관 덤프를 입력으로 쓰지 않았다.

## 구현·검사·운영 결과

양쪽 구현과 관련/전체 편집기 회귀, 독립 검토를 통과했다. 독립 검토로 모바일 실패 후 PC 재시도 성공 시 실패 문구 제거, 같은 정보의 스크롤 반복 안내 방지, 파일 확장자로 실제 형식 단정 금지를 보완했다. 최종 PC 정렬은 각 항목명과 값을10px로 붙이고 줄 전체의 오른쪽 끝을 같게 한다. 행 사이8px·14px/1.55, 제목16px·안내12px, 상세 max440px이며 확장 요약과 빈44px을 제거한다. PC 좁은 요약은14px을 유지하며 한 줄씩 말줄임하고 접근성 이름에 전체 정보를 보존한다.

자체 브라우저 합성 공개41장·편집 작업본42장으로 PC1280px와 모바일390px를 확인했다. PC 상세14px·각 행 오른쪽 끝 일치·gap10px·요약opacity0, 읽기 clientHeight200=scrollHeight200/편집295=295, 편집 닫기 후 본문과 저장상태불변이다. 모바일 공개 헤더60px 아래64px에서13px 정보 한 줄19.5px, 편집 헤더102.5px 아래106.5px에서 두 줄39px를 확인했다. 가로넘침없고 pointer-events:none이며 기존 본문/선택을 가로채지 않는다. 공개 스크롤 후 사진1→4정보로 갱신됐다. 화면 크기 제어는 활성화한 탭에서만 즉시 보였으므로 요청값 대신 실제 DOM폭을 기록했다.

그룹의 다른 사진도 정보 확인이 가능하도록 공개 모바일에서 사진을 누르면 현재 정보 대상을 바꾸고, 선택 사진이 안 보이면 기본 스크롤 대상으로 복귀한다. 기존 링크 기본동작을 막지 않고 내용을 쓰지 않는다. 이 보완 뒤 관련·전체 회귀·소스 빌드를 통과했다.

좁은 사진 배치 후속 전 소스 빌드는1435경로·privateLeak0·surface SHA256 `b2e737a0cfece923be673cc1e1a9f989ef126e1848b78d95b9063ad66e5f5210`로 통과했다. 운영 반영·긴 실제 ICC프로필 표시 확인은 아직 진행 중이다.

## 좁은 사진 배치 후속

검사 후 사용자가 여러 사진 배열로 물리적 공간이 적을 때 팝업/말풍선 등 다른 스타일을 요청했다. PC에서 사진폭이440px보다 좁거나 상세 높이가 사진에 맞지 않으면 사진폭 밖에 읽기폭을 확보하는 말풍선형 팝업으로 전환한다. 해당 팝업만 진한 배경과 흰 글씨로 분리하고 선택사진을 꼬리로 가리킨다. 넓은 사진의 무배경·짙은 글자 그림자는 유지하며230px보다 좁은 요약은 간결한 정보 버튼으로 표시하고 전체 정보를 접근성 이름에 유지한다. 모바일 상단 항상 표시 정책은 유지한다. 양쪽 구현 하위를 같은 소유 파일에서 다시 실행했고 독립 검토는 읽기 전용이다.

양쪽 담당 회귀와 전체 편집기 회귀가 통과했다. 새 CSS 이름에 따른 경로 목록 변화는 재생성해1435경로·SHA256 `77bc0e80f1255a8191b2f085e0bb874aa821ce7397d79f5593da633d17339db1`로 갱신했다. 공개1280px의 사진3/6에서440px 말풍선·208px 전체 높이·94% 배경·그림자 없음·좌우 꼬리·잘린 숫자 대신 정보 버튼을 확인했다. 모바일390px는 헤더 아래64px·13px·가로넘침 없이 상단 정보를 표시하고 나란히 있는 사진3을 누르면 사진3으로 바뀌며 상세 팝업은 숨김을 확인했다.

실제 합성 편집 화면에서 사진6 말풍선이 편집 도구 회피용 요약 좌표를 따라 사진5 쪽으로 이동하는 문제를 찾았다. 사진6 실제 위치를 팝업/꼬리 기준으로 보완했고 이전 요약과 팝업 사이의 hover 이동도 연결했다. 최종 자체 브라우저에서 사진6 top326.12px·중앙x187.98px에 맞춰 팝업 top332.12px·꼬리 중앙187.98px를 확인했다. 팝업440×303px·상세 clientHeight295=scrollHeight295이며 닫기 후 본문/저장 상태도 같았다. 독립 검토의 매우 짧은 공개 화면 헤더 판별도 보완해800×120은 가용공간 부족 시 숨김,800×160은 헤더·꼬리·화면 하단 안쪽으로 표시하는 관련 검사를 통과했다.

위 두 보완을 포함한 최종 소스에서 전체 편집기 회귀·소스 빌드·요구사항 검사·독립 검토를 통과했다. 빌드1435경로·privateLeak0·최종 surface SHA256은 `77bc0e80f1255a8191b2f085e0bb874aa821ce7397d79f5593da633d17339db1`이다. 실제 글·사진·작업본 쓰기/공개는 없다. Git 동기화와 양쪽 실제 운영 반영·긴 실제 ICC프로필 표시 확인이 다음이다.
