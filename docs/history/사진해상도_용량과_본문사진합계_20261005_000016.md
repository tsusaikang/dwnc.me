## 후속 범위 변경

2026-10-05 사용자가 색영역·HDR 등 의미 있는 사진 정보 표시와 읽기 화면의 개별 정보 표시를 요청했다. 앞선 읽기 개별정보 비표시 조건은 대체됐다. 기존 해상도/용량·합계 구현을 유지하며 작은 사진 정보 도구에서 형식·색영역·HDR을 확인하도록 확장한다. 파일에서 확정할 수 없는 정보는 미확인으로 표시하며 촬영장소 등 무관한 개인 EXIF는 노출하지 않는다. JPEG 최종 파일의 크기와 원본 대비 압축률은 구분하고, 인코더의 품질값을 압축률로 표시하지 않는다.

서버/검사 담당은 메타데이터 추출·접근정책, 편집 담당은 편집기 정보도구, 독립 검토 담당은 공개 정보도구 구현으로 역할을 조정했다. 메인이 최종 통합·독립 검토를 맡는다. 세부정보는 선택한 사진의 제한된 범위만 읽고 전체 사진 원본을 추가 다운로드하지 않는다. JPEG/Ultra HDR 근거는 공식 libjpeg-turbo 문서와 Android Ultra HDR 규격을 참조한다.

## 구현과 로컬 확인

- `photo-media-summary.ts`와 `native-post-store.ts`: 표시 중인 반영본문의 사진 개수·고유 파일 bytes 합계. 공개 요약에는 작업본이나 미사용 업로드를 넣지 않으며 조회 실패·외부 사진의 용량은 확인 불가로 남긴다. 정적 글과 동적 글에 같은 표시 기준을 적용했다.
- `photo-file-metadata.ts`·`photo-media-info.ts`: 관리자는 해당 글 소유 사진, 공개는 기존 공개·예약·보호·본문참조 검사를 통과한 사진만 조회한다. 요청한 파일의 앞부분 최대256KiB를 읽고 저장 용량·형식·픽셀·JPEG EXIF 회전·ICC 색영역/프로필·HDR 기록을 판독한다. R2 객체 크기·형식·해시 계약과 이관 사진 manifest를 재사용한다. DB 쓰기·사진 재압축은 없다.
- JPEG 색상 프로필명만으로 색영역을 추정하지 않는다. 지원하는 ICC 행렬·전달특성으로 sRGB/Display P3를 판별하고 기타는 미확인으로 남긴다. HDR은 메타데이터의 기록 여부이며, orphan XMP도 실제 HDR 영상 검증과 구분한다. AVIF 등 판독하지 못한 항목은 미확인이다. 촬영장소 같은 개인 EXIF는 제공하지 않는다. 원본 대비 JPEG 압축률이나 인코더 품질 수치를 만들어 표시하지 않는다.
- 편집 기본 해상도/용량 표시는 저장 본문 밖 overlay이며 업로드·글 전환·늦은 응답을 처리한다. 폭105px 미만 사진은 번호와 정보 버튼을 세로 배치하여44px 터치영역과 옆 사진 분리를 유지한다. 읽기 화면의 정보 버튼도 본문 DOM을 감싸거나 변경하지 않으며 클릭할 때만 상세 조회한다. 모달의 Escape·초점 복귀·오류 재시도·중복 조회 캐시를 확인했다.
- 전체 `editor:test` 통과. 새 합계·파일정보·공개 정보 UI 검사와 기존 이미지 이동/그룹/undo/붙여넣기·권한·공개 분리 회귀를 포함한다. 실제 생성한 sRGB/Display P3 JPEG, EXIF 회전, HDR 메타데이터·불완전 헤더, PNG/GIF/WebP/AVIF 미확인 처리, 비공개/예약/보호/타 글·외부경로 차단, 최대 조회 범위·DB무변경을 확인했다. `check` 오류0·경고0(기존 힌트만), 요구사항 검사·diff 검사 통과.
- 메인 자체 브라우저의 로컬41장 반영본/42장 작업본 합성 사례에서 공개 `본문 사진 41장 · 총 375.07 KB`(375,069바이트), 첫 사진1600×900·9,048바이트를 확인했다. 작업본의 추가 중복 사진은 공개 합계에 섞이지 않았다. 편집 정보 열기/닫기 전후 전체본문·저장footer불변을 비교했다. 390px에서78×94px 그룹사진의44×91px 세로 도구, 나머지 사진과 비겹침, 상세정보 모달과 가로넘침없음·Escape초점복귀를 확인했다. 실제 휴대폰 터치는 미시험이다.
- 첫 빌드는 새 공개 CSS 해시와 정적 허용경로 목록 불일치로 중단됐다. 기존 생성기로 `public-request-surface-v1.json`을 갱신했으며 경로 수1,432개는 동일하다. surface·redirect·remote-build·bundle 검사와 최종 `cloudflare:build:source` 전체 빌드를 통과했다. 과거 이관 콘텐츠는 빌드 입력 검증일 뿐 이번 기능의 운영 콘텐츠 입력으로 쓰지 않았다.
