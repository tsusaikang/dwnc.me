## 요청·완료 조건

기본 정보에 마우스를 올린 뒤 상세 조회를 시작해 대기하는 문제와, 상세 줄의 오른쪽 끝이 기본 줄보다 안쪽으로 밀리는 문제를 개선한다. PC 화면 가까운 사진은 미리 준비하고 성공 결과·진행 중 요청을 재사용한다. 모바일 기본값, 파일 판독·권한·범위 조회, 실제 콘텐츠·사진·저장/공개 정책을 보존한다. 기존 Git 자동 배포와 공개/편집 운영 확인까지 완료한다.

## 최신 운영 읽기와 결정

공개 기본 줄 오른쪽1322.066px, 상세1305.321px로 약17px 오차였다. 브라우저 innerWidth1422px가 스크롤바를 포함하지만 고정 위치 기준은 document clientWidth1405px이므로 상세가 안쪽으로 밀렸다. 편집 화면720px 높이에서는 내부 스크롤바15px가 별도 오차를 만들었다. 기존 기본 정보 위치는 옮기지 않는다.

## 구현

- 공통 `src/lib/photo-info-preload.ts`: PC 현재 화면의 위아래600px 안에 있는 사진을 idle 작업으로 동시 최대2개 선조회한다. 성공·진행 중 요청은 기존 cache에서 공유하고 선조회 실패는 조용히 남겨 수동 열기 때 재시도한다. 화면 밖·모바일에서 새 선조회는 하지 않는다.
- 공개 `src/lib/public-photo-info.ts`: 성공 정보는 상세 열기 때 동기로 표시해 대기 문구를 건너뛴다. 스크롤바를 제외한 폭으로 고정 오른쪽 위치를 계산한다. 사진 주소 변경·추가·제거와 늦은 이전 응답을 처리한다.
- 편집 `src/lib/admin-image-direct.ts`: 같은 선조회·완료정보 재사용을 적용하고 글 전환 때 캐시 소유자와 늦은 응답을 구분한다. 기존 본문·선택·저장과 분리된 정보 영역만 변경한다. 공개 plain/편집 overlay 투명 상세에서만 내부 스크롤바 여백을 숨기고 스크롤 기능을 유지한다.

메인은 사용자 로그인 브라우저 읽기와 로컬 합성 화면 확인, 통합·공식 상태를 맡고 하위 에이전트가 구현·회귀와 독립 검토를 맡았다. 브라우저 세션 기능에 대한 직접 확인은 메인만 수행했다.
