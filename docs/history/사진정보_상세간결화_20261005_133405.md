# 사진 상세 정보 간결화와 편집 스크롤 보완

## 요청·완료조건

2026-10-05 사용자가 공개·편집 상세의 느슨한 줄 간격·불규칙한 키/값 정렬·두 단위의 저장용량·형식 한 줄 낭비·사진번호 제목·HDR 유의사항과 편집 내부 스크롤을 지적했다. 기존 CORE-041의 직접 후속이며 `1559ebe`·미커밋 없음에서 시작한다.

형식·해상도·용량은 기본 한 줄로 묶고, 보이는 사진번호 제목·원시 바이트 중복·HDR 주의/저장 기준 문구를 제거한다. 색영역·프로필·HDR은 고정 키 열·왼쪽 값 열,14px/1.45와4px 행 간격으로 정돈한다. 대상 사진은 접근성 이름과 기존 말풍선 꼬리에 유지한다. 모바일은 현재 사진·헤더 마지막 행·슬래시 표시를 유지하며 번호/주의 문구를 줄인다. 파일에서 확실하게 읽은 HDR 방식·수치를 표시하고 미확인을 SDR로 단정하지 않는다. 읽는 파일 범위는256KiB를 유지한다.

편집은 이전 높이 제한을 해제해 자연 높이를 측정하고 가용공간과 방향을 정한 뒤 필요한 경우만 제한한다. 충분한 PC 화면에서는 상세 전체가 내부 스크롤 없이 표시돼야 하며, 짧은 화면에서 넘치는 내용을 단순히 잘라 숨기지 않는다. 공개·편집 관련/전체 회귀·독립 검토·최종 빌드·PC/모바일 자체 브라우저와 최신 양쪽 운영 확인·Git 동기화가 완료조건이다.

## 역할·이번 운영 조회

하위 public_info_layout은 공개 표시/스타일/검사, editor_info_layout은 편집 표시/높이/검사, mobile_info_review는 HDR 판독/관련 검사를 맡는다. 메인은 조정·통합·실제 브라우저·전체 검사·공식 상태·Git을 담당한다. 사용자의 브라우저 세션 동작은 메인이 최소 범위로 직접 확인한다.

이번 조회에서 공개 #600은9사진·총8.26MB, 편집 #600은9사진·공개와 같은 작업본·마지막 저장2026-09-22 23:31:48 KST다. 첨부 사진1은666096바이트, 사진3은579404바이트의 현재 공개 파일이다. 조회 후 사용자 변경 가능성을 유지하며 이관 덤프를 현재 입력으로 쓰지 않는다. 실제 글·사진·작업본 쓰기, 공개 전환, 권한 변경은 요청 범위에 없다.

## 구현·검사

양쪽 기본값 한 줄·64px 키/값 grid·14px/1.45·4px 행 간격·제목/바이트/안내 제거를 구현했다. 프로필이 없거나 색영역과 같으면 생략하고 HDR은 공유 `src/lib/photo-info-presentation.ts`로 표시한다. 원시 버전 코드 대신 방식과 기록된 수치만 화면에 둔다. 배열1/3채널과 명시된0값·false는 보존한다. 편집은 이전 제한 높이와 flex 축소 상태에서 다음 높이를 측정하던 문제를 고쳐 panel auto·dialog maxHeight none·overflow visible로 자연 높이를 읽고 실제 부족할 때만 제한한다.

`photo-file-metadata.ts`에 이름공간을 확인하는 제한된 XMP 판독과 알려진 ISO v0 수치 판독을 추가했다. Apple·Adobe·ISO 방식과 기록된 게인맵/HDR 여유(스톱), Apple 밝기 여유(배수), 기준 영상만 반환하며 기본값을 만들지 않는다. 추가 전체 파일·확장 XMP·게인맵 조회는 없다. 독립 검토에서 같은 이름공간의 서로 다른 prefix가 같은 속성을 중복 선언할 때 마지막 값이 덮어쓰이는 문제를 발견해 packet 거부와 관련 검사를 추가했다. 미래 버전·잘림·예약 비트·0분모·역전/충돌 수치는 제외한다. API 전달/권한은 기존 경로를 그대로 사용한다.

판독 근거는 [Android Ultra HDR 규격](https://developer.android.com/media/platform/hdr-image-format), [Google libultrahdr ISO 구현](https://raw.githubusercontent.com/google/libultrahdr/main/lib/src/gainmapmetadata.cpp), [Skia Apple XMP 처리](https://skia.googlesource.com/skia/+/main/src/codec/SkXmp.cpp)다. 게인맵 파일 내용이나 실제 화면 HDR 렌더링을 검증하는 기능은 아니다.

관련/전체 편집기 회귀·독립 검토를 통과했다. 합성 PC1280×800에서 양쪽 상세 높이84.89px/client85=scroll85, 키/값 시작점이 행마다 같았으며 편집 overflow visible·maxHeight none였다. 본문과 편집 저장 상태는 열기/닫기 전후 같았다. 모바일390×844는 양쪽 헤더 마지막 행·번호 없는 슬래시·가로넘침없음을 확인했다. 최종 새 CSS 경로 목록은1435개·surface SHA256 `6c24885632edbd51d7eade6c802972469587cb607c3a3ed98f781f0dbbcd3bdb`로 갱신했다. 첫 빌드의 경로 목록 변경 검사는 이 재생성 후 최종 소스 빌드에서 다시 확인한다.

하위의 두 실제 공개 파일 prefix 조회는 로컬 네트워크 제한 뒤 서버403으로 읽지 못해 추가 다운로드를 중단했다. 최종 운영 API/화면 반영에서 실제 파일의 방식과 수치를 확인하며 합성 구현 성공과 구분한다.

최종 소스 빌드·요구사항 검사·diff 검사도 통과했다. 빌드1435경로·privateLeak0·위 새 surface SHA256을 확인했다. 다음은 Git 동기화와 실제 공개/편집 #600의 새 표시·실제 HDR 값·본문/저장 상태 불변 확인이다.

## 배포 형태의 표시 함수 보완

기능 `d5f307d`를 원격 main에 동기화하고 양쪽 새 기본값/제목 제거를 확인했다. 실제 공개 상세는 조회 실패, 편집은 기본값까지만 표시돼 완료로 처리하지 않았다. 편집 브라우저 오류는 공유 함수 내부의 named arrow에 Wrangler keepNames가 붙인 `__name`이 직렬화된 클라이언트 안에 없어서 발생한 ReferenceError였다. 원본 TS/합성 서버의 검사는 이 배포 형태를 검사하지 못했다.
