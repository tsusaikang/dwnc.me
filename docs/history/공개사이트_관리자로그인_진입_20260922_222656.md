# 공개 사이트의 관리자 로그인 진입 링크

- 요구사항: `DWNC-CORE-027`, `PLAN-09`.
- 상태: 최종 소스 `44f6e14`의 공개·관리자 Git 자동 배포와 운영 로그인 진입·관리자 목록 확인 완료. 최초 공개 CI 실패와 수정·재배포 근거는 아래에 보존한다.

## 요청과 결정

사용자는 오래 열린 관리자 세션이나 노트북을 들고 장소를 옮겨 사용하는 중 로그인이 풀렸을 때 공개 사이트에 로그인 버튼이 없어 관리자 주소를 직접 입력해야 하는 불편을 지적했다. 개별 로그인 해제 원인은 아직 확정하지 않으며 이번 보완은 공개 화면의 진입 경로에 집중한다.

공통 헤더에 일반 링크로 `관리자 로그인`을 항상 제공하고 인증된 관리자임이 확인되면 `관리자 화면`으로 표시한다. 세션 만료·통신 실패·JavaScript 미실행에도 기본 링크를 유지한다. 기존 관리 도구막대와 글 편집 링크는 인증 확인 후에만 표시한다.

기존 관리자 편집기의 새 탭 로그인·작성 화면 복귀·재시도와 미저장 입력 보존 경로는 별도 관련 코드·시험으로 확인한다. 24시간 세션·허용 계정·권한·Cloudflare Access/SSO 정책은 유지하고 새 자동 복구·로컬 보관 기능은 추가하지 않는다. 실제 글·작업본·사진·공개 상태를 변경하지 않는다.

## 역할과 확인 범위

구현과 관련 세션 경로 점검은 하위 에이전트, 사용자 세션에 묶인 브라우저·통합·배포 확인은 메인이 맡는다. 이번 요청의 운영 화면 확인은 메인이 별도로 진행하며 이전 600편 목록·글 편집 관측을 이번 로그인 진입 확인의 근거로 대신하지 않는다.

미로그인·인증 성공·세션 만료·통신 실패·JavaScript 없는 진입의 관련 회귀와 화면 확인을 구분한다. 완료조건과 현재 위치는 [현재 요구사항](../REQUIREMENTS.md) 및 [공식 상태](../../PROJECT_STATE.md)를 따른다.

## 로컬 화면·시험 결과

- 1280px PC 화면의 사이드바에서 관리자 로그인 링크를 확인했다. 390×844 화면에서는 첫 줄 브랜드·관리자 로그인, 둘째 줄 기존 메뉴를 유지했다. 실제 문서 폭 375px·화면 폭 390px로 가로 넘침이 없고 링크 높이는 44px이며 해당 위치의 클릭 대상도 링크였다.
- 로컬 합성 서버 `4324`에서 미로그인 → 관리자 인증 → 인증 해제 상태로 바꾸고 각각 새로고침했다. `관리자 로그인` → `관리자 화면` → `관리자 로그인` 문구와 인증 성공 때만 관리 도구가 표시되는 것을 실제 브라우저에서 확인했다.
- 링크는 새 탭 대상으로 구현했지만 도구 클릭 후 새 탭 생성 목록은 확인하지 못했다. 링크의 실제 주소를 그대로 별도 새 탭으로 열어 로컬 관리자 `/#view=posts` 목록에 도착함을 확인했다. 이를 클릭에 의한 새 탭 자동 생성 확인으로 주장하지 않는다.
- 기존 관리자 세션 만료 후 새 탭 로그인·작성 화면 복귀·입력 보존 경로 관련 시험이 통과했다. 세션 기간·SSO·권한은 변경하지 않았고 새 복구·로컬 보관 기능은 추가하지 않았다.
- 최종 빌드에서 CSS 파일 내용 변경에 따른 공개 파일 목록의 해시 경로 한 개를 갱신했다. 최종 소스 빌드는 성공했고 기존 힌트 22개를 유지했다. Git 배포 진입점 합성 시험도 통과했다.

## 최초 CI 실패와 수정

처음에는 Cloudflare 대시보드 홈·로그인 화면이 빈 화면이어서 연결 상태를 확인하지 못했으나 새 탭에서 복구됐고 메인이 프로젝트 계정 확인값과 일치함을 확인했다. 빈 화면을 사용자 로그아웃이나 인증 해제로 판단하지 않았다. 하위 에이전트가 접근할 수 없는 인증 브라우저 확인은 메인이 맡았으며 운영 글·작업본·사진·공개 상태는 변경하지 않았다.

기능 소스 `f659af1`을 원격 `main`에 전달했다. 관리자 CI는 Success였지만 공개 CI는 활성화 전 빌드 단계의 `scripts/test-cloudflare-artifact.mjs:444:10`에서 `false !== true`로 실패했다. 따라서 관리자 성공을 공개 사이트의 새 로그인 링크 반영 완료로 취급하지 않는다.

로컬에서 출력 시간 제한 뒤 지연된 정리와 바깥 실행 제한의 경합을 원인으로 확인했다. `scripts/run-with-staging-smoke-token.mjs`를 6줄 범위로 최소 수정하고 `test-cloudflare-artifact`에 바쁜 반복 상황 회귀를 보강했다. 강화 회귀·smoke-token 시험·최종 소스 빌드가 모두 통과했고 수정 소스 `44f6e14`를 커밋·원격 푸시했다. 이후 Cloudflare 재배포와 운영 확인은 아래 최종 결과에서 별도로 확인했다. 로컬 시험 성공만으로 운영 복구 완료를 판정하지 않았다.

작업 중 표 기능에 관한 별도 질문은 설명 범위로 다뤘다. 셀 안 커서에서 표 편집 도구 사용과 HTML 편집을 통한 삭제는 가능하지만 표 전체 선택 표시·전체 삭제 전용 버튼은 없음을 구분했고 관련 시험을 확인했다. 표 코드 수정이나 새 요구사항 등록으로 확대하지 않았다.

세션 기간·허용 계정·권한·Access/SSO 정책을 바꾸지 않았고 새 자동 복구·로컬 임시저장 기능은 추가하지 않았다. `CORE-027`은 안정 ID와 완료조건을 그대로 보존해 [완료 원장](../REQUIREMENTS_ARCHIVE.md)으로 옮겼다. 현재 미해결과 다음 행동은 [공식 상태](../../PROJECT_STATE.md)를 따른다.
