기존 글·사진·서식·주소와 작업본/공개 반영본을 보존하며 블로그를 지속 운영한다. 이번 요청은 인수인계 준비다. 새 기능·대기 항목·실제 콘텐츠 작업에는 착수하지 않았다.

먼저 [AGENTS.md](../../AGENTS.md), [PROJECT_STATE.md](../../PROJECT_STATE.md), [현재 요구사항](../REQUIREMENTS.md)과 이 문서를 읽는다. 재개 기준은 **원격 `main`의 최신 문서 커밋까지 포함한 상태**다. 인수인계 착수 시 `main`의 HEAD는 기록 커밋 `0492b53`, 미커밋 변경 없음, 로컬과 `origin/main` 차이는 0/0이었다. 이번 인수인계 문서 커밋은 이보다 뒤에 추가된다. 기능 기준선과 기록 커밋을 구분한다.

## 최근 완료와 사용자 동작

**사진 번호와 숫자로 순서 이동(`DWNC-CORE-038`)을 구현·배포했다.** 휴대폰·AI 편집에서 드래그를 대체할 수 있도록 사진의 현재 순서를 표시하고 원하는 최종 순번을 입력하게 했다. 기존에는 드래그와 방향키 이동이 있었으므로 마우스만 가능했던 것은 아니다.

1. 본문 사진이나 사진 번호를 눌러 선택한다.
2. `옮길 번호`에 이동 후의 최종 순번을 입력한다.
3. `번호로 이동`을 누르거나 Enter를 입력한다. 이동 후 전체 번호가 다시 매겨진다.

같은 그룹은 재정렬한다. 다른 그룹의 내부 순번으로 이동하면 해당 경계에서 행을 나누고 독립 사진으로 놓는다. 공통 설명은 원래 앞쪽 행에, 개별 설명은 해당 사진에 보존하며 이동·분리는 한 번의 실행 취소로 되돌린다. 번호는 편집 도구에만 표시하고 저장·미리보기·공개 본문에는 넣지 않는다. 잘못된 번호와 같은 순번은 본문을 바꾸지 않는다. 일반 문단이나 표 하나에 여러 사진이 섞인 내부 위치로 이동하려 하면 서식 보존을 위해 거부하고 별도 사진 문단으로 분리하도록 안내한다.

## 재개 시 유지할 원칙

- 자동저장은 작업본 저장이며 공개 반영과 별개다. 실제 콘텐츠를 쓰면 최신 revision 충돌 방지를 유지하고 미공개 작업본 덮어쓰기·요청 없는 공개를 하지 않는다. 기존 실제 글을 기능 시험에 사용하지 않는다.
- 브라우저는 Codex 자체 브라우저만 사용한다. 새 세션·탭·프로젝트에서는 로그인·대상 계정을 재확인하고, Cloudflare 작업 전 계정 확인값을 프로젝트 기준과 대조한다. 로그인 정보는 사용자가 직접 입력하며 비밀값·비공개 원문·로컬 인증을 Git과 인수인계에 넣지 않는다.
- 메인은 조정·통합·공식 상태·사용자 세션을 맡고 주요 실무는 하위 에이전트에 위임한다. 사용자 브라우저 등 접근 불가가 확인되면 메인이 필요한 동작만 직접 수행한다.
- 마감에는 저장소 관리 대상 변경을 공식 상태에 반영하고 커밋·푸시한다. `main` 문서만 푸시해도 Cloudflare 자동 빌드가 시작될 수 있다. 문서 전달과 기능 변경을 구분한다. 삭제·외부 전송·권한·비용·공개 전환의 승인 범위를 임의 확대하지 않는다.
- Cloudflare 런타임에서는 `redirect: 'error'`가 실제 장애를 일으켰다. 관련 파일 전달은 `manual`과 응답 검사로 처리하며 로컬 모의시험·빌드 성공만으로 운영 성공을 단정하지 않는다. 직접 배포·주소/권한 변경으로 승인된 Git 전달 경로를 우회하지 않는다.
