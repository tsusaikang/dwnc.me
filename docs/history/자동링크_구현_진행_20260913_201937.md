# CORE-017 자동 링크 구현 진행 기록

2026-09-13 KST. 정본: [공식 상태](../../PROJECT_STATE.md), [현재 요구사항](../REQUIREMENTS.md). 완료 기록이 아니다.

## 사용자 결정과 완료조건

원래 링크가 없던 이전 글 596편은 그대로 둔다. 새 입력·붙여넣기 웹주소 자동 링크와 선택적 해제를 구현하고 티스토리 UX를 참고한다. 자체 서비스 작성 중 이 기능이 없어 링크가 빠진 글은 보완한다. 최종 소스 Git 자동 배포와 운영 확인까지 완료해야 한다.

## 구현과 파일

- `src/lib/admin-autolink.ts`: 새 입력 범위를 추적하여 http(s)/www 주소를 공백·Enter·붙여넣기 때 링크로 만든다. 기존 링크·코드·명시적 해제 영역을 제외한다. 기존 본문을 열거나 저장하는 서버 경로에는 자동 변환을 넣지 않았다.
- `src/lib/admin-ui.ts`, `admin-formatting.ts`, `admin-editor-history.ts`: 기존 편집기에 연결하고 재열기·실행 취소에서 새 입력 범위를 초기화한다.
- `src/lib/native-content.ts`: span의 `data-dwnc-no-autolink`만 추가 허용하여 링크 해제 의도를 저장·재열기 후에도 유지한다. 반복 적용/해제는 기존 표식을 재사용한다.
- `scripts/test-editor-autolink.mjs`, `package.json`: 관련 회귀와 전체 시험 연결. 프로토콜/www 없는 도메인 단독 문자열은 파일명·기술명 오인식을 피하려 자동 변환하지 않으며 기존 수동 링크를 사용할 수 있다.

현재 해제 조작은 링크에 커서를 둔 뒤 기존 툴바 ‘링크’ → ‘링크 해제’다. 티스토리 최신 화면에서도 같은 흐름을 확인해 이 UI를 유지한다.

## 로컬 검증

최종 `editor:test`, `cloudflare:build:source`, `git diff --check` 통과. 오류·경고 0, 기존 힌트 21. source-only 빌드의 미디어 사본 및 비공개 누출 검출 0. 앱 변경은 하위 에이전트가 수행하고 메인이 내장 브라우저의 로컬 합성 화면을 확인했다.

메인 브라우저에서 확인한 동작:

- 주소 입력 후 Space/Enter 자동 링크, 빈 다음 줄의 커서 위치 유지.
- Enter 뒤 plain text 붙여넣기 즉시 링크 생성, www 주소의 https 연결, 링크 뒤 일반 글자·한글을 링크 밖에 입력.
- 링크 해제, 실행 취소로 링크 복원, 다시 실행으로 해제, 저장·목록·재열기 후 해제 유지.
- HTML 편집으로 링크 없는 기존 URL을 저장한 뒤 재열기하고 정확히 URL 뒤에 공백·Enter를 넣어도 미링크 유지.

중간 브라우저 확인에서 붙여넣기의 빈 BR 교체와 Enter 후 커서 역이동을 발견하여 수정한 뒤 재확인했다. 독립 리뷰에서 괄호 뒤 한글 조사와 인접 텍스트 노드 경계 문제를 발견하여 수정·회귀를 확인했다. 실제 운영 편집기 시험과 실제 IME 조합 입력은 하지 않았고, IME는 자동시험 범위다. 최종 표식 재사용 소규모 보완은 자동시험·빌드로 확인했다.

로컬 fixture 실행: `node scripts/serve-editor-fixture.mjs`, 관리자 `http://127.0.0.1:4322/`. 실제 글과 연결되지 않은 합성 데이터다. 최종 로그는 `/tmp/dwnc-core017-editor-final.log`, `/tmp/dwnc-core017-build-final.log`이며 Git 전달 대상이 아니다.

## 운영 자체 글 보완

2026-09-13 사용자 로그인 승인 후 관리자 목록에 598개가 표시됐다. 이전 596편, 자체 작성 실제 글 `/posts/597`, 기존 비공개 합성 시험 글 한 개를 구분했다. 전체 휴지통/삭제 행까지 재집계한 결과는 아니다. 이전 596편은 수정하지 않았다.

키보드 글은 편집 전 ‘작업본 저장됨 · 공개 내용과 같습니다’여서 다른 미반영 편집이 없었다. Logitech 도움말 URL 한 곳만 링크로 바꿔 21:56:36 KST 공개 반영을 확인했다. 브라우저의 텍스트 선택이 앞 BR까지 포함한 첫 시도는 실행 취소하여 기존 HTML 복원을 확인했다. 이어 제품의 HTML 편집으로 정확한 URL만 anchor 처리했다. 기존 sanitizer가 사진 4개의 속성 없는 span 포장을 제거했으며, anchor를 제거한 결과가 원본의 그 포장만 제거한 결과와 정확히 같았다. 글자·사진·사진 속성·나머지 서식은 유지했다. 임시 비교 HTML은 브라우저 메모리에만 두었고 문서에 복제하지 않았다.

독립 읽기 확인에서 `https://dwnc.me/posts/597?preview=1`은 HTTP 200이며 Logitech URL 텍스트와 정확한 href를 가진 링크 한 개다. curl User-Agent와 preview 제외를 사용했고 외부 링크나 이전 글을 방문하지 않았다.

## 티스토리 실제 UX와 로그인

과거 공개 검색의 [2006 공식 가이드](https://notice.tistory.com/589)는 최신 UX 근거로 사용하지 않았다. 초기 자동 승인 검토가 로그인·저장 계정 선택을 차단했고 사용자에게 이유를 설명했다. 이후 사용자가 기존 로그인과 프로젝트 계정 사용을 명시 승인했고 이번에 올바른 티스토리·관리자 세션 접근을 확인했다. Cloudflare도 화면 Account ID를 프로젝트의 저장된 SHA256 확인값과 대조해 일치함을 확인했다. 비밀번호·토큰·계정 이메일은 기록하지 않는다.

`dwnc.tistory.com/manage/newpost`의 기존 합성 사진 시험 내용에서 example.com URL 입력+공백으로 자동 링크를 확인했다. 링크 클릭만으로 팝업이 열리지는 않으며 툴바 ‘링크 삽입/수정’을 누르면 URL·대체텍스트·새창으로 열기·링크해제·확인 화면이 나온다. ‘링크해제’ 후 주소 글자는 남았다. 임시저장·완료·발행 버튼은 누르지 않았으며 기존 실제 글은 열거나 수정하지 않았다. 편집기 자체 자동 보관 여부는 별도로 단정하지 않는다.

## 최종 통합 진행

작업 브랜치는 `codex/core017-autolink`다. 주요 앱 구현은 하위 에이전트, 브라우저·운영 글 보완·통합·공식 기록은 메인이 맡았다. 최종 stale paste 합성 반례(실제 삽입 없는 paste 뒤 일반 Space가 이전 URL을 후보로 만드는 경우)를 막았다. 내장 브라우저의 명령 기반 붙여넣기는 synthetic paste 뒤 beforeinput 없이 insertText를 보냈다. insertFromPaste 또는 실제 insertText data가 clipboard 전체 문자열과 정확히 같은 경우만 허용하여 두 경로를 지원한다. 일반 Space에는 이전 paste 내용을 전용하지 않는다. 임시 fixture 진단을 제거한 최종 화면에서 새글 빈본문 URL 붙여넣기 즉시 anchor, Enter 다음줄의 직접 입력+Space anchor를 확인했다. 진단 중 cua.typeText는 trusted beforeinput/input이었으며 advanced locator.type은 같은 경로라고 가정하지 않는다. JS 오류는 없었다.

다음 순서: 최종 로컬 시험 종료 → 최종 소스 main 푸시와 공개/관리자 Git 자동 배포 확인 → 공식 상태/완료 원장 마감. 승인된 기능·배포 범위의 재승인은 필요하지 않다.
