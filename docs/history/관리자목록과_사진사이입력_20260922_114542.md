## 변경과 근거

관리자 목록에서 실제 제목을 첫 줄에 단독 표시하고 순번·유형·공개 상태를 별도 줄로 분리했다. 공개 상태는 작은 표시로 구분하며 날짜·미공개 변경 안내·검색·정렬·편집 진입과 자동저장 뒤 목록 갱신을 유지한다. 저장 제목에서 문자열을 제거하거나 운영 데이터를 재작성하지 않는다.

연속 사진 블록 사이 바깥 여백을 클릭하면 빈 문단과 커서를 만들고 기존 빈 문단은 재사용한다. 여백에 마우스를 올리면 `＋ 글 쓰기` 안내를 보여준다. 사진·캡션·그룹 안쪽·드래그 조작과 구분하며 원본·순서·그룹·캡션·문단 서식, 기존 실행 취소/다시 실행·작업본 자동저장·공개 반영 분리를 유지한다.

구현·관련 시험은 하위 에이전트가 맡고 메인은 사용자 로그인 세션이 필요한 운영 읽기와 내장 브라우저·통합·Git 배포를 담당한다. 주요 변경은 `src/lib/admin-ui.ts`, `src/lib/admin-image-direct.ts`, 관련 시험과 `scripts/serve-editor-fixture.mjs`다.

## 로컬 내장 브라우저 확인

- 1280×720 합성 편집기에서 사진 사이 실제 화면 좌표를 클릭해 `p/br` 문단을 만들고 문장을 입력했다. 실행 취소 2회로 원래 사진 4개 구조를 복원하고 다시 실행 2회로 문장을 복원했다. 자동저장 뒤 새로고침·재열기에서도 입력 문장·사진 4개·캡션을 유지했다.
- 390×844는 실제 `innerWidth`·`innerHeight`를 확인한 작은 화면이다. 사진 B/C 사이 여백을 클릭해 문단·문장을 입력하고 캡션 보존을 확인했다. 실제 휴대폰 터치 시험은 아니다.
- 작은 화면의 첫 시도에서는 스크린샷으로 추정한 좌표가 캡션을 가리켰다. 실행 취소로 복원하고 현재 요소의 화면 좌표를 확인한 뒤 재시험에 성공했다. 도구 좌표 선택 오류를 제품 결함이나 첫 시도 성공으로 기록하지 않는다.
