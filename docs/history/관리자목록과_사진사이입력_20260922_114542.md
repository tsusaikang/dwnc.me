## 변경과 근거

관리자 목록에서 실제 제목을 첫 줄에 단독 표시하고 순번·유형·공개 상태를 별도 줄로 분리했다. 공개 상태는 작은 표시로 구분하며 날짜·미공개 변경 안내·검색·정렬·편집 진입과 자동저장 뒤 목록 갱신을 유지한다. 저장 제목에서 문자열을 제거하거나 운영 데이터를 재작성하지 않는다.

연속 사진 블록 사이 바깥 여백을 클릭하면 빈 문단과 커서를 만들고 기존 빈 문단은 재사용한다. 여백에 마우스를 올리면 `＋ 글 쓰기` 안내를 보여준다. 사진·캡션·그룹 안쪽·드래그 조작과 구분하며 원본·순서·그룹·캡션·문단 서식, 기존 실행 취소/다시 실행·작업본 자동저장·공개 반영 분리를 유지한다.

구현·관련 시험은 하위 에이전트가 맡고 메인은 사용자 로그인 세션이 필요한 운영 읽기와 내장 브라우저·통합·Git 배포를 담당한다. 주요 변경은 `src/lib/admin-ui.ts`, `src/lib/admin-image-direct.ts`, 관련 시험과 `scripts/serve-editor-fixture.mjs`다.

## 이번 운영 조회 · 2026-09-22

메인이 기존 Google 로그인을 선택해 관리자에 접속하고 현재 목록 총 600편을 읽었다. 목록의 #600·#599·#594에서 제목 앞에 유형·공개 상태가 연달아 표시되는 기존 동작을 확인했다. 이는 사용자 첨부 화면과 별도로 이번에 읽은 현재 운영 결과다.

#600의 현재 작업본은 사진 `figure` 9개가 연속되고 그 사이 문단은 0개였다. 마지막 저장 시각은 2026-09-22 11:35:13 KST이고 공개 반영을 기다리는 변경이 있었다. 첨부 화면과 이번 조회 시점의 작업본 상태가 다름을 구분했다. 이번 운영 조회에서는 입력·저장·공개를 하지 않았다. 개별 제목·본문·사진 내용은 이 기록에 남기지 않는다.

## 로컬 내장 브라우저 확인

- 1280×720 합성 편집기에서 사진 사이 실제 화면 좌표를 클릭해 `p/br` 문단을 만들고 문장을 입력했다. 실행 취소 2회로 원래 사진 4개 구조를 복원하고 다시 실행 2회로 문장을 복원했다. 자동저장 뒤 새로고침·재열기에서도 입력 문장·사진 4개·캡션을 유지했다.
- 390×844는 실제 `innerWidth`·`innerHeight`를 확인한 작은 화면이다. 사진 B/C 사이 여백을 클릭해 문단·문장을 입력하고 캡션 보존을 확인했다. 실제 휴대폰 터치 시험은 아니다.
- 작은 화면의 첫 시도에서는 스크린샷으로 추정한 좌표가 캡션을 가리켰다. 실행 취소로 복원하고 현재 요소의 화면 좌표를 확인한 뒤 재시험에 성공했다. 도구 좌표 선택 오류를 제품 결함이나 첫 시도 성공으로 기록하지 않는다.

사진 직접조작·배치·본문 이력·작업본·관리자 UI·CMS 관련 회귀가 통과했다. Git 배포 진입점 합성 시험(`cloudflare:git:test`)도 통과했다. 최종 `cloudflare:build:source`는 종료 코드 0이며 Astro 오류·경고 0, 기존 힌트 22개로 정적 출력·공개/관리자 소스 번들을 완성했다.

전체 편집기 시험 중 기존 `scripts/test-native-editor.mjs:376`의 홈 목록 `li > a` 검사(기대 7, 실제 0)가 실패했다. 직전 [붙여넣기 완료 기록](본문_붙여넣기_단축키_20260917_013542.md)에도 있던 홈 카드 검사 불일치이며 이번 범위에서 수정하지 않았다. 따라서 전체 `editor:test` 통과를 주장하지 않는다. 관련 회귀·최종 빌드 성공과 이 기존 실패를 구분한다.

## Git 전달과 남은 확인

기능 소스 `c062486`을 2026-09-22 원격 `main`에 푸시했다. Cloudflare 대시보드는 재로그인이 필요해 사용자 직접 로그인을 요청했다. 관리자 사이트 로그인과 기존 운영 읽기는 성공했다. 11:52 KST 새로고침 후에도 운영 목록은 기존 표시였다. 자동 배포 실패인지 진행 중인지는 대시보드에 로그인하지 못해 확인하지 못했으며, 새 UI 운영 반영을 완료로 판정하지 않았다.

공개·관리자 배포 결과와 운영 목록·편집기 반영을 읽기 확인한다. 그 결과를 이 기록과 [공식 상태](../../PROJECT_STATE.md)에 추가한 뒤 두 요구사항을 완료 원장으로 옮긴다. 현재 요구사항은 `in-progress`이며 기존 운영 글에 대한 시험 입력·저장·공개를 하지 않는다.
