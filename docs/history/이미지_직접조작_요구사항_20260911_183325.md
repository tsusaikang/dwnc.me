# 이미지 직접 조작 요구사항

작성: 2026-09-11 KST · `DWNC-CORE-014` · `PLAN-09` · 상태: 완료 (2026-09-12)

## 목표

별도 모달 중심의 사진 배치를 본문에서 직접 끌어 놓는 조작으로 개선한다. 티스토리 실제 편집기를 내장 브라우저로 먼저 사용해 사진 이동·묶기·분리의 동작을 관찰하고 그 결과를 구현에 반영한다. 완료된 `CORE-013`은 [완료 기록](신규_기능_요구사항_20260911_173052.md)에 그대로 보존하며 이번 요청은 별도 후속 기능이다.

## 승인 범위와 보존 경계

- 사용자는 티스토리 실사용 관찰과 개선 구현을 요청했다. 티스토리에서는 기존 게시물을 변경·발행하지 않고 새 미저장 시험 범위로 확인한다. 자동 임시저장 등 실제 동작이 이 범위를 벗어나면 먼저 그 영향을 구분한다.
- 사용자는 실제 dwnc.me에 신규 비공개 합성 시험 글 **하나**를 생성·수정해 확인하는 것을 명시 승인했다. 이는 기존 실제 글 변경·삭제 허가가 아니다. 시험 글 삭제는 별도 승인이 필요하며 공개 전환은 하지 않는다.
- 원본·비공개 실제 콘텐츠·로그인 정보·비밀값을 출력·로그·문서·Git에 기록하지 않는다. 합성 시험 자료만 사용한다.
- 기존 Git 배포 경로와 새 소스 빌드 원칙을 유지한다. raw 배포·DNS/route 변경·R2 덮어쓰기/삭제를 하지 않는다. 구현·로컬 확인·운영 반영·실제 시험 결과를 구분한다.

## 현재 상태와 다음 행동

메인이 내장 브라우저에서 티스토리 로그인과 빈 새 글쓰기 화면을 확인하고 합성 PNG 3장으로 직접 관찰했다. 이 결과를 전달받은 하위 에이전트의 구현과 로컬 확인을 완료했다. 최종 소스 a7b76ff의 Git 자동 배포와 새 비공개 합성 시험 글 1개의 실제 시험까지 완료했다. 운영 관리자 내부 글 목록 진입은 확인했고 기존 글 내용은 출력하거나 변경하지 않았다. 메인은 브라우저·통합·공식 상태를, 하위 에이전트는 주요 구현을 담당한다. [공식 상태](../../PROJECT_STATE.md)를 기준으로 이어간다.

### 구현·로컬 확인 결과 (2026-09-11)

- `src/lib/admin-image-direct.ts`에 드래그 문단 이동·2/3장 묶기·그룹 분리/순서·인라인 정렬/크기와 이동 손잡이를 추가했다. `admin-ui.ts`가 기존 본문 이력·자동저장·사진 선택에 연결한다. 기존 모달은 선택적 배치 더보기로 남는다.
- 글자와 섞인 사진은 문단 밖으로 끌어낸 뒤 그룹·정렬·크기를 적용하도록 안내한다. 문단 안에 잘못된 블록을 삽입해 뒤쪽 글자 서식을 바꾸지 않는다.
- 실제 로컬 브라우저에서 A/B 묶기 → C 추가 → C/A/B 순서 → C를 두 문단 사이로 분리 이동, 개별 캡션·굵게/기울임·표 보존을 확인했다. 분리 실행 취소와 다시 실행 결과가 정확히 일치했고, 자동저장 후 목록→재열기에서도 HTML이 일치했다.
- 작은 원본 320px은 문단/전체 폭 선택이 비활성이고 우측 정렬해도 320px이다. 큰 원본 1400px은 문단 폭을 선택해 720px 표시를 확인했다.
- 390×844 화면에서 이동 손잡이로 2/3장 묶기와 그룹 순서를 바꾸고, 모바일 미리보기의 사진·캡션·본문·표와 가로 넘침 없음을 확인했다. 이는 브라우저의 모바일 크기 시험과 포인터 조작이며 실제 휴대폰 터치 실기는 아니다.
- `editor:test`, 요구사항 검사/시험, Git 배포 진입점 합성 시험, 최종 source-only 빌드 통과. 빌드는 오류·경고 0, dist 미디어 파일 0이다. 기존 staging 타이머 시험의 첫 일시 실패는 단독/전체 재시험에서 통과했으며 해당 시험을 수정하지 않았다.

### 티스토리 관찰 결과 (2026-09-11)

- 사진 B를 A의 오른쪽 가장자리로 끌면 A/B 2장 그룹, C를 오른쪽에 놓으면 3장 그룹이 됐다.
- 그룹의 C를 A 왼쪽 가장자리로 놓아 C/A/B 순서로 바꿨다. C를 A 사진 내부의 상단 가장자리로 놓으면 C 단독 사진과 A/B 2장 그룹으로 분리됐다.
- 그룹 바깥의 빈 여백과 문단 영역으로 놓은 여러 시도는 이동되지 않았다. 티스토리의 문단 사이 이동 성공으로 간주하지 않는다. 우리 편집기에서는 문단 경계를 넓고 명확한 놓기 대상으로 제공하고 실제 이동을 확인한다.
- 단독 사진 바로 위 도구에서 너비 500 입력과 왼쪽 정렬을 적용해 표시가 바뀌었다. 본문 폭 맞춤·좌/중/우 도구를 확인했다. 그룹 내부 사진 선택 때는 이미지 편집·대체 텍스트 도구가 표시됐다.
- 티스토리 그룹에는 공통 캡션 입력이 표시됐다. 우리 구현은 기존 각 사진의 캡션 보존을 우선하며 공통 캡션으로 강제 변환하지 않는다.
- 티스토리 새 화면에 합성 문구를 입력한 뒤 자동 저장 완료가 표시됐다. 명시적 임시저장 개수는 0이었고 임시저장·완료·발행을 누르지 않았다. 자동저장 데이터의 서버 보관 범위는 확인하지 않았다. 기존 글은 열거나 변경하지 않았다.
