## 후속 요청: 현재 콘텐츠 정본

작은 카드 수정 배포 중 사용자는 내부/외부 판별·대표이미지·요약 전체 조사 필요성을 제기했고, 그보다 먼저 이관 덤프가 운영 후 편집·신규 글을 반영하지 못하는 문제의 대응을 요청했다. 메인은 전수조사나 일괄 콘텐츠 변경을 시작하지 않고 하위 에이전트에 현재 읽기/저장 경로를 읽기 전용으로 조사하도록 맡겼다.

현재 코드에서 D1의 `legacy_posts`는 이관된 글의 최신 반영본이며 `native_posts`는 신규 글의 최신 반영본이다. `editor_working_copies`는 미공개 작업본이다. 파일명에 legacy가 있어도 그 DB 행을 오래된 원본 덤프와 혼동하지 않는다. 관리자 편집은 작업본을 우선하고 발행은 그 내용을 현재 DB 본문에 반영하며 `src/data/posts`를 수정 입력으로 사용하지 않는다. 과거 공개 원본의6글7카드 조사는 원인/영향의 과거 기준선 확인이며 현재 전체 조사 완료가 아니다.

정본 원칙은 공식 상태와 현재 요구사항의 작업 순서에 반영했다. 현재 운영 전체 목록·본문·대표이미지·요약 및 작업본의 실데이터 전수조회는 아직 하지 않았다. 덤프와 정적 fallback 파일을 제거하거나 재이관하지 않았다. 후속 전수조사는 최신 공개 반영본과 실제 화면을 기준으로 하며 미공개 작업본은 별도 취급한다.

코드 근거: `native-post-store.ts:229`/`:296` 작업본 읽기·저장, `:336`/`:363` 현재 revision 기반 공개 반영, `:416` 공개 본문 조회. `native-public-worker.ts:216`은 현재 DB 목록 우선 병합이며 `:364`/`:380`은 DB 미관리 과거 글에만 정적 fallback을 허용한다. 597 이상 및 DB가 관리하는 비공개/초안은 fallback 대상이 아니다. 별도 이관 SQL도 `scripts/lib/legacy-post-import.mjs:104`의 `INSERT OR IGNORE` 및 `import_complete=0` 조건으로 완료 행을 덮지 않는다. 통상 Git 배포는 DB 재이관을 호출하지 않는다.

카드 제목·요약은 현행 DB 본문 안에 저장된 metadata이며 연결 대상의 최신 내용으로 자동 갱신하는 기능은 없다. 따라서 운영 최신 데이터를 기준으로 검사해도 카드 설명 자체가 과거 상태인 문제는 별도로 식별해야 한다. 현재 수정이 카드 제목·요약의 최신화까지 해결했다고 주장하지 않는다. DB 행 소실/미완료로 인한 정적 fallback 가능성은 코드 경로이며 실제 운영에서 그런 글이 있는지는 미조사다.
