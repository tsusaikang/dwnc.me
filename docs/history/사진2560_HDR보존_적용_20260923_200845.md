# 신규·기존 첨부 사진 2560px·HDR 보존 적용

기준: 2026-09-23 KST. 요구사항 `DWNC-CORE-032`. 최종 운영 결과는 [공식 상태](../../PROJECT_STATE.md)를 따른다.

## 결정과 구현

사용자가 긴 변2560px를 확정하고 새 블로그 생성 후 기존 업로드와 이후 편집기 업로드 모두 적용하도록 요청했다. 품질80, 종횡비 유지·무확대, 목표500KB~1MB는 강제 상한이 아니다. 과거 네이버·티스토리 이관 사진은 제외한다.

파일 선택과 클립보드는 `src/lib/admin-image-upload.ts`의 같은 준비 경로를 사용한다. JPEG는 Google libultrahdr1.4.0·libjpeg-turbo3.0.1을 Emscripten4.0.14로 빌드한 WASM과 module Worker로 처리한다. HDR/SDR를 같은 선형광 Lanczos 방식으로 줄이고 HDR gain map을 재생성한다. 원본 ICC와 HDR 표시 밝기 범위를 유지한다. JPEG 외 정지 이미지의 실제 투명 여부·애니메이션 보존·25MiB 입력 제한·작은 입력 팽창 방지를 유지한다. 지원 밖 색상/HDR은 명시적으로 중단하며 SDR로 우회하지 않는다. [지원 범위와 재현](../../scripts/image-codecs/README.md).

실행 자산은 `public/image-codecs/`6개, 허용목록은 `src/data/image-codec-assets.json`이다. 공개 자산과 관리자 고정 프록시로 같은 출처에서 읽으며 인증 헤더·쿠키는 공개 호스트에 전달하지 않는다. worker/script/WASM에 필요한 CSP만 확장했다. source-only 빌드는 정확한6개를 복사한다. 개발 중 private 벤더 소스가 Astro 검사를 오염시키지 않도록 tsconfig에서 migration/private·tmp를 제외했다.

## 기존 사진 조사와 준비 당시 기록

이번 Cloudflare D1 콘솔에서 native_media23개110207991bytes, legacy_media의native경로2731개1316018054bytes를 조회했다. 경로만으로 신규사진을 구별할 수 없다. 이관기는 원글 발행일을 첨부 생성일로 기록한다. legacy2731개 전부 두 날짜가 같고 최신2022-09-13이어서 제외했다.

현재 공개597/599/600/601/602응답을 읽어17개103773480bytes를 받았다. 실제투명0, 5991개+6009개가2560초과HDR/P3다. 나머지7개는이미기준이하. DB와 공개 목록 차이3개는 최신 공개/작업본 본문과 대표사진 어디에도 참조되지 않음을 확인했다. 그중 #599의 예전 JPEG는3072×4096·6142188bytes로 추가 변환이 남았다. 나머지는 #597의201041bytes PNG와 #601의64445bytes JPEG다. #598은 기존 비공개 합성시험3개로 제외한다.

공개 초과10장 축소본은 원본99778503bytes→8782697bytes(91.20%감소), 장당518497~1455257bytes다. 최대2560px·ICC동일·EXIF방향·HDR표시범위 보존 및 독립 native HDR decode 통과. 현재17사진 합계는 적용하면12777674bytes가 된다. 상세 측정은 `public-conversion-results.json`, 조회 기록은 `live-d1-ui-summary.json`, 미실행 교체 계획과 SQL은 `pending-replacements.json`·`pending-replacements.sql`에 보존했다. 모두 아래 Git 제외 폴더 안이다.

기존native의id/public_path를유지하고 새object_key/sha/bytes/mime만 CAS교체하는 방식을 실제서빙모듈+합성DB로 확인했다. 본문·사용자편집·revision·작업본·공개정책·대표사진은 바꾸지 않는다. 모든 대상의현재metadata가맞을때만단일UPDATE가성공하며 replay/stale/newkey충돌을거부한다. 준비도구 `scripts/prepare-native-media-replacement.mjs`는 SQL생성만하며운영실행은없다.

## 기존 사진 운영 적용 완료와 당시 삭제 승인 대기

사용자가 인증 연결을 승인했다. 계정 전체 D1 권한 토큰 연결은 자동 승인 검토에서 거절돼 발급하지 않았고 권한을 제거했다. 실제 인증은 native 미디어 버킷 한 곳만 허용하는 7일 만료(2026-10-01) R2 토큰으로 제한했다. D1은 기존 로그인된 공식 콘솔에서만 조회·단일 CAS UPDATE했다. 다른 프로젝트 CLI 인증은 변경하지 않았다. 비밀값은 Git 제외 로컬 파일에만 두며 문서에 기록하지 않는다. 인증 입력 서버와 탭은 종료했고, 토큰은 삭제 승인 질문의 응답을 기다리는 동안 아직 유효하다.

미참조 #599 원본도3072×4096에서1920×2560·417305bytes로 변환했다. 미참조 #601 사진은1363×936·64445bytes로 유지하며 남은 미참조 PNG는 기존 소형 이미지와 SHA가 동일하다. 시험용3개 제외 신규첨부20개 전체가 기준 이하이고 이관2731개는 변경하지 않았다.

교체11개 합계105920691→9200002bytes. 모두 HDR/P3·ICC·방향·HDR 표시 범위 보존과 독립 HDR 디코딩을 확인했다. 신규 객체 업로드 후 같은id/public_path를 유지한 D1 조건부 교체11행이 성공했다. 후속 원장 native23행13487302bytes, 옛키 native/legacy 참조 모두0이다. 글 및 작업본6개 revision은 불변이다. 공개사진10개는 실제 HTTP200·SHA·bytes·MIME·2560px 이하 일치, 미참조1개는 공개404 유지다. 로컬 원본11개도 교체전 SHA/bytes와 일치한다.

운영 근거는 Git 제외 `migration/private/native2560_20260923/`의 `live-d1-application.json`, `live-verification.json`, `unused-conversion-result.json`, `unused-small-verification.json`, `cleanup-status.json`에 보존했다. 실행 도구는 `scripts/execute-native-media-replacement.mjs`이며 R2 전용 모드는 D1 API를 호출하지 않는다.

R2 원본 삭제는 아직0이다. 원본105.92MB와 신규9.20MB가 공존하므로 이번 교체만으로 저장소가 줄었다고 말하지 않는다. 원본 삭제 후 교체 전보다96720689bytes(96.72MB)가 감소한다. 삭제 도구는 로컬 원본·신규객체·옛객체를 검증한 뒤 옛키에 If-Match 조건부 DELETE와 HEAD404 확인을 적용하도록 준비했다. 기존 R2 시험132항목과 모의삭제11건 통과, 실제삭제 명령은 JPEG 원본 삭제의 명시승인 부족으로 자동 승인 검토에서 거절됐다. 우회 없이 사용자에게 별도 삭제 승인을 질문했다.

당시 다음 행동은 응답에 따라 원본11개만 정리하거나 보존하고 임시 인증을 폐기하는 것이었다. 무관한 미참조2개·이관 사진·신규 파일은 삭제하지 않는다. 사진 축소·운영 교체 완료와 원본 삭제 승인 대기를 구분한다.

## 후속 승인과 원본 정리 완료

사용자가 “교체전 원본 삭제해야지. 원본 사본 이 컴퓨터에 있는것도 굳이 가지고 있을 필요 있을까”라고 명시했다. 이 승인에 따라 교체가 끝난 R2 원본11개(105920691bytes)를 조건부 삭제하고 각 객체의 HEAD404를 확인했다. 신규 축소본11개(9200002bytes)는 유지하며 교체 전 대비 실제 저장소 감소는96720689bytes다. 위 자동 승인 거절과 승인 대기는 당시 기록이며 현재 미해결 상태가 아니다.

로컬에서는 이번 최적화·비교 작업 폴더에서 교체 전11장과 SHA가 일치하는 사본15개(144552797bytes)를 삭제했다. 최적화 원본11개와 비교용 중복4개이며 삭제 후 파일 부재를 확인했다. 개인 사진 보관함·Google 포토·과거 이관 원본은 건드리지 않았다. 기존 로컬 비교 페이지의 원본 보기는 더 이상 사용할 수 없고 압축본은 유지한다. 원본 사본을 이 컴퓨터에 계속 보존한다는 이전 설명은 이 후속 승인으로 종료됐다.

삭제 후 공개사진10개 HTTP200·신규 SHA/bytes 일치와 미참조1개 공개404 유지를 다시 확인했다. 임시 R2 토큰은 공식 관리 화면에서 폐기 후 목록의 해당 항목0개를 확인했고 로컬 인증 파일도 삭제했다. 다른 프로젝트 인증은 유지했다.

실행 결과는 Git 제외 `migration/private/native2560_20260923/cleanup-status.json`, 정확한 로컬 삭제 대상과 결과는 `migration/private/local-original-cleanup-plan.json`에 기록했다. 무관한 미참조 객체·이관 사진·축소본·본문·작업본·공개 상태는 변경하지 않았다.
