# 공개사이트 로그인 통합

- 요구사항: `DWNC-CORE-037`, `PLAN-09`.
- 목표: 공개 글은 비로그인으로 열람하고 dwnc.me에서 기존 관리자로 로그인하면 관리 메뉴와 글별 편집 버튼을 표시한다. admin.dwnc.me는 같은 Access 앱의 인증을 사용한다.
- 사용자 확정: 공개 블로그의 비공개·예약·보호 글 표시 확장은 제외한다. 실제 글·작업본·사진·공개 구분 쓰기는 없다.

## 결정과 구현

사이트 전체를 Access로 막으면 비로그인 열람이 불가능하므로 `dwnc.me/auth/*`와 기존 `admin.dwnc.me`만 한 Access 앱으로 연결했다. 기존 허용 계정·Google/OTP·24시간 세션과 관리자 서버 권한 검사를 유지한다. 공개 Worker의 `/auth/login`은 서명·허용 계정·만료 검증 후 원래 공개 페이지로 복귀하고 `/auth/session`은 인증 여부만 반환한다. 서버는 쿠키 단독 인증을 하지 않는다. Access의 세션 폐기와 Binding 검사는 해당 보호 경로의 edge가 담당한다.

프런트의 세션 확인은 기존 다른 도메인 CORS 호출에서 같은 도메인 호출로 변경했다. 미로그인 리다이렉트를 따라가지 않으며 실패·만료·잘못된 응답·늦은 응답은 관리자 도구를 숨긴다. 로그인 전 같은 탭에서 인증한 뒤 페이지·검색값·본문 위치를 보존하고 로그인 후 관리자 화면·편집은 기존 새 탭 흐름이다.

구현 위치: `src/lib/public-auth.ts`, `src/worker.ts`, `src/lib/public-admin-links.ts`, `wrangler.jsonc`. 구성 검사·생성 타입·관련 테스트와 `package.json` 시험 묶음을 함께 갱신했다.

## 검증과 운영

- 신규 인증 시험: 위조·만료·다른 issuer/audience/email·외부 Origin·쿠키 단독 우회 거부, 외부/중첩인코딩/인증루프 복귀 차단, 한글·공백·fragment 복귀, 공개 경로 보존 및 인증 경로 DB 접근 없음 통과.
- 전체 `editor:test`, `cloudflare:config:check`, `cloudflare:wrangler:types:check`, `cloudflare:git:test`, `cloudflare:build:source`, 요구사항 검사와 diff 공백 검사 통과. 빌드 공개 산출물 비공개 노출 검사0.
- 하위 에이전트가 backend·프런트를 구현하고 독립 리뷰했다. 메인은 사용자 로그인 브라우저와 운영 설정을 직접 다루고 결과를 통합했다.
- 운영 계정은 화면의 계정 ID를 프로젝트의 기존 `cloudflare-account-id-v1` 확인값과 대조해 일치했다. 기존 관리자 앱의 Google·이메일 OTP·24시간 세션과 허용 정책을 유지한 채 `dwnc.me/auth/*`를 추가 저장했다. 다른 거래원장 앱/공유 정책은 변경하지 않았다.
- 추가 저장 후 비인증 HTTP 확인: 공개 홈200, `/auth/session`302. 코드 배포 전 확인이므로 실제 로그인 기능 완료와 구분한다.
- 기능 커밋 `9180488c5df315cb095e60d9744fe511c3f280f1`은 작업 브랜치와 원격 main에 푸시했다. 공개 Build `3d1fc7f8-2bd5-41bb-8702-0236cfbac6de`의 성공을 화면에서 확인했다.
- 운영 공개 홈페이지의 새 로그인 링크에서 기존 Google 계정을 선택해 인증했다. dwnc.me 복귀 후 글 관리·새 글·통계·설정, 최근 글 편집 링크가 표시됐다. 같은 세션으로 admin.dwnc.me에 추가 로그인 없이 진입해 글 목록과 새 글/통계 버튼 활성화를 확인했다. 실제 글·작업본 쓰기는 없었다.
- `/auth/login?return=%2Farchive%23main`으로 기존 인증을 사용해 `/archive#main` 복귀, 관리자 메뉴 및 공개 글357편의 편집 링크를 확인했다. 공개 목록의 비공개 범위를 변경하지 않았다.
- Access의 기존 AUD와 production 구성 일치, cookie path 제한 끔, Eager redirect cookie 켬을 운영 화면에서 확인했다. 해당 쿠키 옵션·로그인 방법·허용 정책은 변경하지 않았다.
- 운영 관리자 Worker 기본 `dwnc-me-admin.dwnc.workers.dev`는 저장소의 false와 달리 켜져 있었고 preview는 꺼져 있었다. 따라서 중복 앱을 바로 제거하지 않았다. 기본 주소 비활성 및 중복 앱 삭제에 대해 브라우저 도구의 실행 직전 삭제 확인을 요청했다.
- 관리자 Build `492fad8c-570d-47aa-bbff-779a8a3ec150`은 빌드 완료 후 업로드 단계에서 실패했다. 활성화는 시도되지 않았고 기존 관리자 서비스는 정상이다. 같은 기능 커밋 재시도 Build `ef9c22f2`는 22:04 KST 업로드·활성화·빌드 성공을 로그에서 확인했다. 관리자 versions upload dry-run도 로컬에서 통과했다. 첫 실패의 구체 원인은 로그에서 확인되지 않으므로 일시 오류로 단정하지 않는다.
