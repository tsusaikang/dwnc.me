# 공개 사진 원본 크기 새 창

2026-10-06 KST · `DWNC-CORE-045` · `PLAN-09`.

사용자는 사진 클릭 시 실제 별도 브라우저 창에서 원래 크기로 보고 간단한 창 모양을 원했다. 공개 글의 사진 자체에 적용한다고 확인했다. 편집 화면의 사진 선택·이동 동작은 유지한다. 현재 제공 파일의 원래 픽셀 크기를 사용하고 큰 사진은 스크롤한다. 업로드 전 삭제된 원본 파일 복원이 아니며 변환·재업로드·본문 저장을 하지 않는다.

같은 사이트 /media 사진 중 기존 링크/카드가 없는 사진에 적용한다. 현재 창의 본문/미디어 접근정책은 그대로이며 새 창도 같은 사진 주소로 요청한다. 최소 UI 팝업을 요청하되 주소창·창/탭 모양은 브라우저가 결정한다. 팝업 차단 시 새 탭 열기 링크를 제공한다. 마우스 수정키·선택과 키보드 열기·상세 hover를 보존한다.

## 구현과 검사

`src/lib/public-photo-window.ts`의 공개 bootstrap을 정적 PostLayout과 native-public-worker에 모두 연결했다. `src/pages/photo-viewer.astro`는 별도 레이아웃 없이 사진만 표시하고 naturalWidth/naturalHeight를 CSS 크기로 지정해 창맞춤 축소를 하지 않는다. 현재 제공 파일의 인코딩된 pathname과 native query를 유지한다. 미디어 서버와 기존 권한 검사를 그대로 거치고 프록시·변환 경로는 만들지 않는다. noindex/nofollow와 사이트맵 제외를 적용했다.

사용자 클릭 순간 최소 UI 옵션으로 빈 팝업을 열고 opener를 끊은 뒤 보기 페이지로 이동한다. 창 생성·opener 분리·이동 오류를 함께 처리해 실패한 소유 빈 창을 닫고 실행 가능한 새 탭 링크를 제공한다. noopener를 처음부터 지정하면 정상 생성도 null을 반환할 수 있으므로 빈 창을 생성한 뒤 즉시 분리하는 방식을 택했다. 주소창 제거는 브라우저 결정이며 보장하지 않는다.

실행 중 사진에 role/button·tabindex0·이름·data 속성만 보완하며 저장 본문은 쓰지 않는다. 기존 링크·카드·외부 사진·사진 custom role·수정키·반복/조합 키·선택 영역은 개입하지 않는다. 직접 클릭과 Enter/Space를 지원한다. 새 사진과 주소/alt 변경을 관찰하며 PC 상세 hover와 편집 선택 동작은 별개로 유지한다.
