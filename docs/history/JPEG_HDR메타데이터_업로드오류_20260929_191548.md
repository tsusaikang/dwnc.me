# JPEG 업로드 오류 수정

2026-09-29. CORE-034. 기능 커밋 `71eebcb`를 main에 푸시했으며 Cloudflare 자동 배포 확인 중이다.

## 원인과 변경

사용자 보고 파일은 580927바이트,3072×4096 Display-P3 JPEG다. legacy HDR XMP에는 gain map을 선언하지만 파일은 주사진 EOI에서 끝나며 실제 gain map이 없다. 기존 WASM은 이를 Unsupported or damaged HDR gain map으로 거절했다.

`public/image-codecs/jpeg-metadata.js`는 완전한 단일 JPEG임을 확인한 경우에만 orphan legacy HDR XMP를 메모리에서 제거한다. MPF·ISO·extended XMP·추가 이미지·잔여 데이터·잘린 파일은 수정하지 않고 기존 codec 검사에 넘긴다. 원본 파일은 변경하지 않으며 일반 SDR fallback은 추가하지 않았다. helper는 관리자 자산 허용목록에도 등록했다. WASM/C++는 변경하지 않았다.

사진 처리 실패에 `image_processing_failed`를 부여해 로그인 버튼과 분리했다. 실제 인증/연결 오류의 로그인 복구는 유지한다.

## 확인

- 실제 파일로 shipped WASM 및 실제 브라우저 normalizeUploadImage 처리 성공:1920×2560,457463바이트,Display-P3 ICC 바이트 동일.
- 실제 HDR 표본4개는 전처리에서 변경되지 않았다.
- 새 JPEG 경계 회귀, 편집기 전체 회귀, requirements validation, build, diff check 통과.
- 로컬 임시 시험만 수행. 실제 작성 중 글·작업본·공개 내용·R2 변경 없음. 사용자 Chrome 편집기를 재로드하지 않았다.
- 하위 에이전트가 처리기와 오류 UI를 나눠 수정했고 메인은 실제 브라우저 시험·통합·배포 확인을 담당했다.

## 당시 남은 작업

Cloudflare 세션이 만료되어 사용자에게 로그인을 요청했다. 공개 자산과 관리자 배포 반영 확인 후 CORE-034를 완료 원장으로 이동한다. 기능은 GitHub에 저장됐으나 이 기록 시점 운영 완료를 선언하지 않는다.

## 배포 누락 보완

후속 로그인 후379c958 배포 실패를 확인했다. 공개 요청 허용목록에 새 helper가 빠져 배포 검사에서 중단됐다. 생성기로 src/data/public-request-surface-v1.json을 갱신하고 실제 build-cloudflare-source 전체 및 cloudflare:git:test가 통과했다. 수정본을 재배포한다.

## 운영 완료

2026-09-29 2999d57 공개/관리자 Cloudflare build 모두 checkmark 성공 확인. 공개 hdr-worker.js 및 jpeg-metadata.js SHA256이 로컬 수정본과 일치한다. 전체 빌드·회귀 확인 완료이며 CORE-034를 완료 원장으로 이동했다. 실제 글·사진 업로드나 공개 쓰기는 하지 않았다. 기존 편집기의 사진 재시도는 새 Worker를 생성하므로 새 처리기를 요청한다.

## 운영 재현으로 재개

사용자가 최신UI에서도 재발을 보고했다. 74cde96의 인증전용 /image-processing-check에서 실제 coolant 파일을 선택해 서버 전송 없이 재현했다. hdr-worker.js/jpeg-metadata.js/hdr-codec.js/hdr-codec.wasm 네 요청 모두502 application/json(65byte), 최종 cause=codec load failed: worker module load failed. 공개주소200과 대조해 관리자->공개 파일전달 실패가 실제남은원인임확인. 앞선 로컬변환과배포성공은 운영실행성공의 증거가아니므로 완료판단철회.

## 실제 실행 옵션 원인 확정

7a59f67 서비스바인딩 이후에도 인증진단4asset모두 codec_upstream_unavailable로실패했다. 하위에이전트가 실제workerd에서 redirect:error 옵션이 TypeError를 던짐을 재현했다. signal유무와무관하며 manual+signal은200성공. Node mock검사에서는이런Workers옵션차이를잡지못했다. manual로 요청하고 status200만수용하여redirect응답거부정책을유지한다.
