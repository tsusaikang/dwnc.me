# CORE-018 같은 카테고리 글 페이지 탐색

2026-09-14 KST 완료. 정본: [공식 상태](../../PROJECT_STATE.md), [완료 요구사항](../REQUIREMENTS_ARCHIVE.md).

## 결정과 범위

기존 목록은 이전 2개·이후 3개 고정이 아니라 현재 글을 제외하고 발행 시각이 가까운 같은 표시 카테고리 글 5개였다. 사용자는 한 화면 5개를 유지하면서 전체 글을 페이지 번호로 탐색하고, 번호 약 7개와 앞뒤 묶음 이동을 요청했다.

새 목록은 최신순 5개, 날짜가 같으면 글 순번 내림차순이다. 첫 화면은 현재 글을 포함하는 페이지이며 현재 글을 표시한다. 번호는 최대 7개씩 표시하고 «/»는 이전·다음 번호 묶음으로 이동한다. 첫·끝 묶음은 해당 이동 버튼을 비활성화한다. 아래 기존 시간순 이전/다음 글의 연결 대상은 유지한다.

정적 Astro와 운영 Worker는 공통 목록 렌더러를 사용한다. 기존 공개 탐색 목록의 제목·주소·날짜·카테고리만 사용하고 비공개 본문·작업본을 추가로 보내지 않는다. 일상 표시 통합을 유지하고 저장된 분류·글 주소·본문을 바꾸지 않는다. 페이지 클릭은 이미 받은 목록 안에서 표시만 바꾸며 서버 요청·추가 글 조회수를 만들지 않는다.

## 진행과 역할

- 구현: 하위 에이전트 `category_pagination`. 독립 소스 검토: `review_category_pages`.
- 메인: 공식 상태·요구사항, 브라우저 조작, 통합 및 Git 배포. 실제 글/작업본 편집이나 운영 데이터 변경은 하지 않는다.
- 시작 Git은 clean main `c28ab26`. 기존 Cloudflare 계정의 화면 Account ID를 저장된 SHA256 확인값과 대조해 일치함을 확인했다. 해당 세션·탭에서만 재사용한다.
- 사용자가 보여준 글은 `/posts/456`의 `230116-22 주간 일상`으로 확인했다. 운영 글 확인에는 `?preview=1`을 사용한다.

## 검증과 남은 작업

공통 구현은 `src/lib/post-category-pagination.ts`, 연결은 `PostLayout.astro`·`[...path].astro`·`native-public-worker.ts`, 스타일은 `global.css`다. CSS 빌드 해시를 반영한 기존 요청 목록 manifest와 관련 회귀 파일도 함께 저장한다. 독립 소스 검토에서 추가 수정 사항은 없었다.

로컬 기존 Astro 서버(4323)를 재사용했다. `/posts/456` 최초 5/22페이지·5행·현재 글 표시, 14페이지 직접 선택, 8~14·15~21·22 묶음 이동과 마지막 3행, 역방향 1페이지 최신 글을 확인했다. 목록 변경 전후 본문 HTML과 URL은 같았다. 실제 viewport 390px에서 문서 scrollWidth도 390px, 번호7개와 양끝 버튼이 가로 넘침 없이 표시됐다. Enter 키 페이지 선택도 확인했고 viewport override는 해제했다. 기존 서버는 종료하지 않는다.

최종 editor:test 전체·신규 페이지 회귀·source-only build 통과. 타입 오류·경고 0, 기존 힌트 21, 빌드 미디어 사본·privateLeak 0. 신규 회귀는 73편 전체 페이지·경계·포커스와 Worker의 기존 공개 스냅샷 범위·원본 DB 불변·목록 이동 조회 호출 0을 확인한다. 정적 공개 349편 전체에 대한 페이지 순서·현재 위치·묶음 경계 검사도 통과했다. 문서 검사/회귀와 diff 검사 통과. GitHub main 푸시·양쪽 자동 배포·운영 읽기 확인이 남았다. 완료 후 요구사항을 완료 원장으로 옮긴다.


## 운영 확인

기능 소스 `11fdd036f39f03cfbbd157dcbd3a94cb3880c6f7`를 GitHub main에 푸시했다. 공개 Git Build는 `8d6e1eb4-ab54-4311-822e-0ee98fa390eb`, 관리자는 `853d4ee0-b71a-4607-bfdd-05f1e5ead1a6`다. 관리자 빌드는 공개 빌드 뒤 순차 시작됐다.

운영 `/posts/456?preview=1#post-related-title`에서 최초 5/22·현재글표시, 8~14 묶음·10페이지선택·5행, 다음묶음과 마지막22·3행·다음버튼비활성, 역방향묶음과 Enter선택을 확인했다. 본문 HTML과 URL은 바뀌지 않았고 페이지 스크립트도 한 개다. 기존 글/작업본·DB·카테고리·주소를 수정하지 않았다.

로컬은 실제390px에서 가로넘침이 없었다. 운영탭은 브라우저 viewport 요청390px가 실제 해당 탭에 적용되지 않고 innerWidth260px·document320px로 관찰됐다. 이는 운영390px 확인 근거가 아니며 로컬 결과와 구분한다. 조작은 성공했고 임시 viewport 설정은 해제했다. 실제 휴대폰 기기 시험은 하지 않았다.

양쪽 Git Build `11fdd03` Success와 공개 Active deployment `0927cf35`·관리자 `58384641`를 확인했다. 완료 정리 중 사용자가 아래 시간순 카드 방향도 맞추도록 요청했다. 왼쪽은 다음 글(더 나중), 오른쪽은 이전 글(더 오래된 글)로 DOM과 정렬을 바꾸고 기존 rel·대상 계산·주소는 유지한다. 첫 글 `/posts/1`에서는 ‘장성실내수영장 탐방기’ 다음 글 카드만 왼쪽에 보여야 한다. 같은 CORE-018의 후속 보완으로 수행한다.

후속 구현은 두 렌더러의 DOM을 next→prev로 바꿨다. 기존 첫째/둘째 카드 정렬 CSS를 그대로 사용해 CSS·요청 manifest 변경은 없다. 로컬1280px의 첫 글에서 next 카드 x368·빈 오른쪽 자리 x733, 중간 `/posts/456`에서 next457 x368·prev455 x733를 확인했다. 연결 대상·rel 의미는 그대로다. Worker 회귀는 첫·끝 글의 빈쪽 자리와 중간 글 순서를 확인했다. 최종 소스 재빌드·배포 확인 후 마감한다.

## 최종 완료

후속 최종 source-only build와 정적 349편 카드 순서 검사까지 통과했다. 최종 기능 소스 `73c856b2608bfc0e610873c336cde683e3a31450`를 main에 커밋·푸시했다. 공개 Git Build `5bf4a466-aed8-44c7-8095-1dd02b413203`, 관리자 `84b9f604-74f3-4a3f-869a-f764136318c0` 모두 Success다. 새로 읽은 Active deployment는 공개 `dc4e36e7`, 관리자 `a335084f`다.

운영 첫 글 `/posts/1?preview=1#post-related-title`에서 실제 viewport 853px, 첫 카드가 rel=next·/posts/2·‘장성실내수영장 탐방기’로 x20, 오른쪽 빈 span은 x431이었다. 카테고리 목록은 현재 글이 있는 22/22페이지다. 중간 `/posts/456?preview=1#post-related-title`은 next457 x20·prev455 x431이며 5/22페이지를 유지했다. 마지막 확인 화면은 첫 글로 돌려 두었다. 운영 글 내용·작업본·원본 분류·주소·통계 데이터는 변경하지 않았다.

CORE-018 완료조건을 완료 원장으로 옮기고 현재 요구사항과 공식 상태를 갱신했다. 이 마감 기록 변경은 서비스 코드를 추가로 바꾸지 않는다. 메인이 사용자 브라우저와 Git 통합·공식 상태를 담당했고, 하위 에이전트가 구현·검사를 맡았다. 남은 검증 한계는 위 운영 390px 및 실제 휴대폰 미확인뿐이며 CORE-012 등 별도 후속 항목은 착수하지 않았다.
