## Microsoft 로그인 추가 준비 종료 — 2026-09-12

사용자가 Microsoft 로그인 추가를 취소했다. 아래는 종료된 준비 이력이며 현재 미해결이나 실행 지시가 아니다. Google 연결과 실제 관리자 로그인을 완료했으므로 `DWNC-OPS-008`은 Microsoft 범위 취소를 명시하고 완료 원장으로 옮겼다.

- Microsoft는 사용자가 회사와 무관한 개인 계정이라고 정정했다. 개인 계정 자체와 포털의 조직 게스트 선택을 구분하며 Automanix 앱 생성·보안 정보 등록·조직 동의는 진행하지 않는다. [Generic OIDC](https://developers.cloudflare.com/cloudflare-one/integrations/identity-providers/generic-oidc/)와 개인 계정 `consumers` endpoint를 사용할 계획이다. 2026-09-12 재개 시 Azure 포털에서 개인 계정을 명시 선택해도 같은 조직 추가 보안 정보 화면으로 돌아와 해당 흐름을 중단했다. 공식 무료 가입 링크에서는 요청 개인 계정으로 회사 인증 없이 `Create your Azure free account`의 Profile information까지 진입했다. `For personal use`를 선택하고 한국어로 전환해 내장 브라우저에 남겼다. 전화번호·본인 확인·카드 및 약관은 사용자 단계로 남았고 가입은 제출하지 않았다. challenge는 일시 오류 안내가 표시됐다. 앱 등록용 개인 디렉터리 존재 여부는 아직 확정할 수 없으며 앱·Microsoft IdP·추가 이메일 설정도 미생성이다.
- 연결 입력: Access team origin은 `https://ancient-term-4cf0.cloudflareaccess.com`, callback은 같은 origin의 `/cdn-cgi/access/callback`이다. Google은 External/Web client로 이 origin과 callback을 등록했다. Microsoft 개인 계정용 앱 audience는 Personal accounts only, OIDC 인증/토큰은 `https://login.microsoftonline.com/consumers/oauth2/v2.0/authorize` 및 `/consumers/oauth2/v2.0/token`, 인증서 주소는 `https://login.microsoftonline.com/consumers/discovery/v2.0/keys`, scope는 `openid profile email`, email claim은 `email`이다. 실제 반환 email 일치를 확인하며 username을 임의로 이메일로 대체하지 않는다.
- Microsoft [앱 등록 가이드](https://learn.microsoft.com/en-us/graph/auth-register-app-v2)는 앱 소유용 Entra 디렉터리를 전제로 한다. 개인 계정으로 로그인하는 것과 회사 계정/조직 소유는 별개다. [디렉터리 전환 안내](https://learn.microsoft.com/en-us/azure/azure-portal/set-preferences)를 따라 본인 소유 공간을 확인해야 하며, 미확인 tenant를 만들거나 회사 tenant를 대신 쓰지 않는다. 독립 디렉터리가 없으면 신규 개인 Azure 가입에 전화·카드 확인이 필요할 수 있다. 개인 Microsoft 홈의 기본 계정은 요청 계정 일치가 확인되지 않아 추가 조작 없이 탭을 닫았다. 로그인 비밀번호·MFA·결제 정보는 수집하지 않았다.

- 취소 시점 최종 확인: 사용자가 가입 2/3 주소 정보·약관 화면까지 진행했으나 주소는 빈칸, 약관은 미동의, Next는 비활성이었다. 가입 완료 상태가 아니며 메인이 가입 탭을 닫았다. 위의 Profile information 기록은 그 이전 준비 시점이다.
