# 사진 그룹 설명과 공통 높이

`DWNC-CORE-036`, 2026-09-30. 사용자 요청: 나란히 배치한 두세 장의 설명은 그룹에 속하며 서로 다른 종횡비도 높이를 맞춘다.

## 변경과 결정

- 어느 사진을 골라도 같은 `그룹 설명 편집`을 열고 설명은 묶음 아래 한 영역에 표시한다. 대체텍스트는 선택 사진에만 적용한다.
- 기존 사진별 설명은 링크·강조·명시 정렬을 보존하여 그룹 설명에 합친다. 한 장 빼내면 설명은 남은 그룹에 유지하고, 전체 해제하면 마지막 사진 아래에 한 번 보존한다. 설명 외의 기존 본문을 버리지 않도록 구조 검사를 유지했다.
- 사진의 가로/세로 비율로 너비를 배분하여 공통 높이를 만든다. 원본 확대·잘림·비율 변형 없이 원본 최소 높이를 상한으로 삼는다. 읽기·이미지 로드 때 계산하므로 기존 저장 그룹도 새로 열면 적용된다.
- 편집기·미리보기·공개 표시가 같은 규칙을 사용한다. 공개 그룹은 좌측 메뉴를 제외한 실제 글 영역 안에 들어오도록 제한한다.
- 실제 글·작업본·미디어 일괄 쓰기 및 공개 전환은 하지 않았다. 메인이 사용자 세션이 필요한 자체 브라우저 조회와 로컬 화면 시험을 담당하고 구현·독립 검토는 하위 에이전트에 위임했다.

## 검증

- 운영 관리자 API가 반환한 최신 작업본을 읽기 전용으로 확인했다. 두 장 그룹 세 개와 1920×2560·2560×1920 혼합 사례의 기존 구조를 확인했으며 원문은 기록하지 않았다. 사용자 수정 중일 수 있으므로 조회 이후 상태를 고정하지 않았다.
- 전체 `npm run editor:test` 통과. 설명 병합/서식·정렬, 사진 이동·분리·해제, 설명 편집, 저장/재열기, 실행 취소 회귀를 보완했다. 독립 검토에서도 관련 다섯 검사 통과, 남은 구체 결함 없음.
- 최종 `npm run cloudflare:build:source` 통과. 공개 산출물 검사와 비공개 누출 검사 통과.
- 실제 자체 브라우저 로컬 합성 사진(600×800, 1000×600, 800×800): 세 장 묶기·다른 사진에서 같은 설명 열기·저장 후 재열기·한 장 빼내기·실행 취소 확인. PC 미리보기 높이 약242.34px, 모바일 미리보기 약95.41px로 동일(서브픽셀 반올림 오차 이내).
- 최종 두 장 그룹 편집기 높이491.58px, 그룹/본문 중심 일치. 로컬 공개 처리기에서 1265px 화면의 메뉴176px를 제외한 글 영역1089px, 그룹1045px·좌우 여백22px, 사진 높이427.445px 동일·수평 넘침 없음. 793px 화면도 그룹749px·높이304.96px·넘침 없음.
- 실제 운영 콘텐츠에 시험 입력은 하지 않았다. 공개 시험은 localhost 합성 데이터에 한정했다.

## 운영 전달

기능 커밋 `0d734bb`를 원격 main에 푸시했고 GitHub Checks에서 `Workers Builds: dwnc-me-admin`, `Workers Builds: dwnc-me` 둘 다 completed/success를 확인했다. 공개 #604 응답에서 새 CSS, 인증 관리자에서 새 그룹 함수를 확인했다.

이후 최신 목록에서 해당 글이 #605 공개 상태로 바뀐 것을 확인했다. 사용자에 의한 상태 변화이며 에이전트의 공개 전환이 아니다. 해당 글을 다시 읽어 편집기 3그룹의 각 두 사진 높이가 각각447.35px·445.5px·570.23px로 일치, 실제 공개 혼합그룹 높이377.92px로 일치함을 확인했다. 편집기 사진 선택 시 그룹 설명 편집 표시도 확인했다. 조회·선택만 했으며 실제 콘텐츠/작업본 쓰기는 없다.

배포 전부터 열려 있던 편집기는 작업본 저장 완료 확인 후 새로 열어야 새 코드가 적용된다. 후속 문서 커밋은 완료 결과 동기화이며 기능 기준선은 0d734bb다.

## 2026-09-30 저녁: 사진 삭제 후 빈 칸 보완

사용자가 한 장 삭제 후 남은 사진이 그룹 전체폭을 차지하지 않는 문제를 보고했다. 최신 운영 #605 작업본(21:04 수정·공개하지 않은 변경)에서 첫 번째 item은 비고 두 번째 item에 사진만 남은 cols-2 구조를 확인했다. 그룹1200px 중 사진594px였다. 같은 시각 공개 반영본은 기존 두 장 그룹을 유지했다. 두 상태를 구분해 읽기만 했으며 실제 글에 시험 삭제·저장·공개를 하지 않았다.

삭제 버튼·Backspace·Delete 처리에 빈 셀 정리와 장수/열비율/원본폭 재계산을 연결했다. 기존 손상 저장본도 편집기 재열기·미리보기·공개 표시의 공통 정리 함수를 사용한다. 남은 한 장에도 공개 가용폭 제한을 적용하며 원본 확대 금지 규칙은 유지한다. 마지막 사진 삭제 시 설명과 비사진 내용은 그룹 밖에 보존한다. 연속 삭제의 이력 경계를 확정하여 단계별 실행 취소·다시 실행을 보존했다.

검증: 전체 editor:test 및 최종 cloudflare:build:source PASS. 신규 실제 삭제 handler 검사3경로×3→2→1→0, 단계별 exact undo/redo, 설명 서식/링크 보존, native/legacy 저장·손상본 재열기 검사 PASS. 빌드와 전체 검사를 동시에 실행한 첫 시도는 생성 중인 dist 파일 부재로 중단됐고, 빌드 완료 후 전체 재실행은 통과했다. 향후 해당 검사는 빌드와 직렬 실행한다. 독립 검토 관련3종 PASS.
