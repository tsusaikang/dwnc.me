# 운영자 점검에서 발견한 결함 보완 요구사항

작성: 2026-09-09 KST · 원장: `DWNC-CORE-012` · 계획: `PLAN-09` · 상태: **등록완료 구현착수대기 (`planned`)**

## 목적과 이번 작업의 경계

기존 기능에서 확인된 실패를 고쳐 작성 내용·사진과 검색 결과가 사용자의 의도대로 유지되게 한다. 사용자 요청에 따라 이번에는 요구사항 작성·등재만 한다. 코드 수정, 신규 시험 작성·실행, 빌드, 배포와 실제 콘텐츠 변경은 시작하지 않는다. 문서 형식 검사는 수행한다. 과거 운영 반영 승인이 있어도 이번 요청을 구현 착수 지시로 해석하지 않는다.

[운영자 상황별 대응 점검](운영자_상황별_대응_점검_20260909_223042.md)의 결함을 원인별 6건으로 묶었다. CSS 배경 사진의 L18/O23은 같은 결함이며, 초안/사진 응답 유실 A16/A28은 서로 다른 저장 경로이므로 각각 관리한다. 현재 소스에는 여섯 건 모두 현실적인 수정 경로가 있다. **수정 불가능하거나 과도하게 어려워 제외할 근거가 있는 결함은 없다.** 난이도는 현재 구조에 대한 상대 평가이며 구현·재현 전 확정 공수나 해결 보증은 아니다.

## 항목별 요구사항과 인수 조건

### F01 — 사진 삭제 실행 취소

- 요구: 본문 사진을 도구막대의 삭제 또는 Delete/Backspace로 지운 뒤 실행 취소 버튼과 지원하는 키보드 단축키로 원래 위치·배치·캡션을 복원한다. 다시 실행으로 동일 사진을 다시 제거한다.
- 인수: 합성 본문의 사진 삭제 → 실행 취소 → 다시 실행이 각각 삭제 → 복원 → 삭제가 되고 주변 텍스트·표·서식과 앞뒤 편집 순서를 훼손하지 않는다. 복원 결과는 기존 작업본 자동저장 흐름에 들어가며 공개 반영 전에는 방문자 본문이 달라지지 않는다.
- 경계: 실제 R2 사진 삭제나 과거 서버 편집본 복원을 추가하지 않는다. HTML 소스 삽입의 실행 취소는 점검에서 미확인이므로 별도 결함으로 확대하지 않는다.
- 소스: `src/lib/admin-ui.ts`의 `deleteSelectedMedia`, `src/lib/admin-formatting.ts`의 서식 명령 실행.

### F02 — CSS 배경 사진의 공개 참조

- 요구: 반영된 본문이 허용된 CSS로 참조하는 해당 글 소유의 내부 배경 사진을 일반 본문 사진과 같은 상태 정책으로 제공한다. 참조 분석 때문에 원래 본문·배치·미디어 주소를 임의 변경하지 않는다.
- 인수: 합성 CSS 배경 전용 사진이 공개 후 표시되고, 예약 시각 전에는 차단·이후에는 표시되며, 보호 글은 인증 전 차단·인증 후 표시된다. 비공개와 다른 글 소유 사진은 차단한다. 작업본에만 추가한 사진은 공개 반영 전 차단하고, 작업본에서만 제거한 기존 반영 사진은 반영 전까지 유지한다. 반영본에서 참조를 제거하면 기존 정책대로 직접 제공을 차단한다.
- 경계: 임의 외부 CSS URL 허용, 미참조 파일 전체 공개, 실제 비공개 글의 시험 공개 전환은 하지 않는다. 기존 이미지·대표사진·영상과 원본 서식은 유지한다.
- 소스: `src/lib/native-post-store.ts`의 `getPublicMedia`, `src/lib/native-content.ts`의 `nativeImagePathsInHtml` 및 HTML 정규화.

### F03 — 검색 실패 안내와 재시도

- 요구: 통신 실패·성공이 아닌 HTTP 응답·해석할 수 없는 응답을 검색 결과 없음과 구별해 안내한다. 사용자가 같은 검색어를 재시도하거나 다른 검색어를 입력하면 새로고침 없이 새 요청으로 회복할 수 있다.
- 인수: 최초 실패 → 연결 회복 → 같은 검색어 재시도에서 정상 결과를 보인다. 실패 응답을 영구 재사용하지 않으며 정상 색인은 기존처럼 재사용할 수 있다. 오류를 처리하지 않은 채 남기지 않고 자동 무한 재시도도 하지 않는다.
- 경계: 한 글자 검색, 결과 수 확대, 검색 엔진 교체는 추가하지 않는다.
- 소스: `src/components/SearchDialog.astro`의 `loadIndex`와 검색 입력 처리.

### F04 — 오래된 검색 응답 무시

- 요구: 현재 입력과 요청에 해당하는 결과·오류만 표시한다. 입력을 지우거나 최소 검색 길이 아래로 줄이면 이전 요청 완료 후에도 결과가 비어 있어야 한다.
- 인수: 느린 검색 A → 입력 삭제, 느린 A → 검색 B, 오래된 A 실패 → B 성공의 합성 순서에서 최종 입력과 맞지 않는 결과·오류가 나타나지 않는다. F03의 재시도와 정상 결과 없음 안내도 유지한다.
- 소스: `src/components/SearchDialog.astro`의 비동기 입력 처리.

### F05 — 초안 생성 응답 유실 후 이어가기

- 요구: 하나의 새 글 생성 요청을 재시도하면 이미 만든 같은 초안을 반환한다. 사용자가 별도로 새 글을 만들면 새 초안을 생성한다. 글·페이지·공지 종류와 기존 번호 부여 시점을 유지한다.
- 인수: 서버 생성 성공 뒤 응답만 유실시키는 합성 상황을 먼저 재현하고, 재시도·동시 재시도에서도 같은 초안 하나로 이어지는지 확인한다. 서로 다른 생성 요청은 별도 초안이 되고, 같은 요청 식별자를 다른 생성 내용에 재사용하면 기존 초안을 잘못 반환하거나 덮어쓰지 않는다. 인증 실패와 재로그인 뒤의 정상 재시도, 기존 작업본 보존을 확인한다.
- 경계: 기존 중복 초안을 일괄 삭제하거나 모든 초안을 전역 중복 제거하지 않는다. 일반 글 삭제 기능을 추가하지 않는다.
- 소스: `src/lib/admin-ui.ts`의 새 글·재시도 처리, `src/admin-worker.ts`의 초안 생성, `src/lib/native-post-store.ts`의 `createDraft`.

### F06 — 사진 업로드 응답 유실 후 이어가기

- 요구: 같은 글에 대한 같은 업로드 요청을 재시도하면 같은 저장 결과를 회복하고 본문 삽입도 한 번만 수행한다. 사용자가 같은 파일을 별도로 다시 삽입하려는 새 요청과 구분한다. 업로드 사진의 크기·형식·내용 확인과 글 소유권·인증을 유지한다.
- 인수: **현재 미실행인 응답 유실 합성 재현부터 확인한다.** 사진과 DB 기록 성공 후 응답 유실 → 재시도, 사진 저장 성공 후 DB 기록 실패 → 재시도, 동시 재시도에서 같은 요청의 R2 객체·미디어 행·본문 삽입이 중복되지 않고 처리가 완료된다. 같은 요청 식별자의 다른 파일·다른 글 재사용은 거절하고 기존 자료를 바꾸지 않는다. 여러 사진 중 일부 실패 후 재개해도 성공한 사진을 중복 삽입하지 않는다.
- 경계: 전역 파일 중복 제거, 기존 중복·미사용 사진 삭제, R2 덮어쓰기·삭제는 포함하지 않는다. 새 영상·임의 첨부 허용도 추가하지 않는다.
- 소스: `src/lib/admin-ui.ts`의 `uploadImage`, `src/admin-worker.ts`의 미디어 저장, `src/lib/native-post-store.ts`의 미디어 기록.

## 제외와 미확인 항목의 구분

- 이번에 어렵거나 불가능해서 제외한 **결함은 없다**. F06의 실제 응답 유실은 아직 합성 재현 전이라는 불확실성을 유지한다.
- 휴지통·일반 글 삭제·과거 버전 복원·강제 종료 후 미저장 입력 복구·백업·전체 복원·내보내기·대규모 부하 대응 등은 기존 미지원·미완료 또는 미확인 사항이다. 이번의 확인된 결함 보완 범위 밖이며, 불가능하다고 판정한 것이 아니다.
- 이미 내려받은 외부 사본을 회수하는 것처럼 서버가 보장할 수 없는 결과는 목표로 삼지 않는다. 댓글·방명록·구독·팀블로그 제외와 광고 후순위의 기존 결정도 유지한다.

## 향후 착수 순서와 전체 완료 조건

사용자의 후속 착수 지시가 있을 때 시작한다. 검색 F03/F04, 편집 F01, 미디어 참조 F02, 생성·업로드 F05/F06의 관련 파일 충돌을 조정하고 필요한 실무는 하위 에이전트에 위임한다. 메인은 통합·내장 브라우저·공식 상태를 맡는다.

전체 완료는 여섯 항목의 합성 실패 재현 해소, 관련 기존 기능 회귀 확인, 메인 내장 브라우저의 합성 편집·검색 확인, **최종 소스로 새로 빌드한 전체 보완의 운영 반영과 읽기 전용 실서비스 확인**까지이다. 이전 배포 번들 재사용이나 일부 항목만 먼저 배포하지 않는다. 지금은 이 완료 조건을 등록하는 단계이며 실행하지 않는다.

실제 글·작업본·사진·공개 주소와 로컬 원본을 보존한다. Git push, raw wrangler deploy, DNS·route 변경, R2 덮어쓰기·삭제, 실제 글 시험 변경·삭제, 비밀값·비공개 콘텐츠의 로그·문서·Git 기록 금지는 유지한다. 검증을 위해 실제 비공개 콘텐츠를 공개하지 않는다.
