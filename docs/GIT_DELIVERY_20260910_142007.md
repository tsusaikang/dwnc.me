# Git에서 Cloudflare로 배포하기

역할: Git 자동 배포의 연결 설정과 실행 계약. 현재 반영된 소스·검증 범위·다음 행동은 [공식 상태](../PROJECT_STATE.md), 연결과 운영 확인의 완료 근거는 [완료 원장](REQUIREMENTS_ARCHIVE.md)의 `DWNC-OPS-007`에서 관리한다. 이 문서는 새 배포나 권한 변경을 승인하지 않는다.

## 연결 대상과 설정

기존 공개 Worker와 관리자 Worker를 각각 같은 저장소·같은 운영 브랜치에 연결한다. 두 Worker에 별도의 Workers Builds가 생기는 Cloudflare 공식 방식을 사용한다. 새 Pages 서비스나 DNS·route 변경은 필요 없다.

| 설정 | 공개 Worker | 관리자 Worker |
|---|---|---|
| Worker 이름 | `dwnc-me` | `dwnc-me-admin` |
| 저장소 루트 | `/` | `/` |
| 빌드 명령 | `npm ci && npm run cloudflare:git:test` | `npm ci && npm run cloudflare:git:test` |
| 배포 명령 | `npm run cloudflare:git:deploy:public` | `npm run cloudflare:git:deploy:admin` |
| 비운영 브랜치 자동 배포 | 끔 | 끔 |

운영 브랜치는 양쪽 모두 원격 기본 브랜치인 `main`이다. `.node-version`의 Node `24.18.0`과 lockfile을 사용한다. `SKIP_DEPENDENCY_INSTALL=1`을 유지하고 위 빌드 명령의 `npm ci`로 의존성을 설치한다. npm은 `10.9.2` 이상 12 미만, Wrangler는 `4.125.0`이다.

배포 명령 안에서 `cloudflare:build:source`를 먼저 실행한다. 따라서 HTML/CSS 등 공개 산출물은 해당 Git 소스에서 매번 새로 만들어지며 기존 로컬 `dist`나 과거 배포 번들을 재사용하지 않는다. 원본·비공개 파일·실제 사진은 빌드 입력에 필요 없다.

## 배포가 하는 일

`scripts/deploy-cloudflare-git.mjs`는 선택된 Worker 하나에 대해서만 다음을 수행한다.

1. 현재 소스를 새로 빌드한다.
2. 해당 production 설정으로 `wrangler versions upload`를 실행한다. 두 `.jsonc` 설정은 현재 주석 없는 순수 JSON이며 실행 진입점은 이를 JSON으로 읽어 production Worker 이름을 확인한다.
3. Wrangler의 구조화된 `version-upload` 결과에서 Worker 이름·환경·버전 ID를 확인한다. 검증된 업로드 event는 Cloudflare가 지정한 원래 출력 파일(우선) 또는 출력 디렉터리에 JSON Lines 형식으로 추가 전달해 Builds 결과 연결에 사용할 수 있게 한다. 기존 파일을 덮어쓰지 않으며 세션 인자 기록은 전달하지 않는다.
4. 그 정확한 ID를 `wrangler versions deploy <ID>@100% --yes`로 활성화한다.

`wrangler deploy`, `triggers deploy`, D1 migration/import, R2 sync·덮어쓰기·삭제는 호출하지 않는다. 기존 dashboard 변수는 `--keep-vars`로 유지하고, 자원 자동 생성은 끈다. 원래 production 설정의 DB·R2 연결을 사용한다.

Cloudflare가 주입하는 `WRANGLER_CI_OVERRIDE_NAME`과 `WRANGLER_CI_MATCH_TAG`는 제거하거나 바꾸지 않는다. 선택한 Worker와 연결된 이름이 다르면 업로드 전에 중단한다. 관리자 코드를 공개 Worker에 잘못 올리는 것을 막기 위한 대상 확인이다.

## 인증과 배포 완료 기준

실행 진입점은 Cloudflare CI의 `CI`, `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`를 요구한다. 연결한 기존 빌드 토큰을 사용하며 자격값은 문서나 로그에 기록하지 않는다.

Worker 버전 업로드·활성화 권한이 필요하다. DB·R2 내용 쓰기나 DNS·route 변경 권한은 이 경로의 작업에 필요 없다. 새 권한이 필요한 설정 변경은 현재 승인 범위와 별도로 판단한다.

두 Builds는 독립 실행된다. 하나가 성공하고 하나가 실패할 수 있으며, 두 Worker를 동시에 바꾸는 원자적 배포를 보장하지 않는다. **둘 다 같은 소스의 배포에 성공하고 운영 상태를 확인해야 전체 전환 완료다.** 활성화 단계 통신 실패는 이미 반영됐을 수도 있으므로 실패 결과만으로 미반영이라 판단하지 않는다. 기존 서비스는 호환 가능한 소스 전환을 전제로 하며 향후 호환성이 깨지는 변경은 별도 순서를 정해야 한다.

## 관련 검사

`npm run cloudflare:git:test`는 실제 외부 연결 없이 빌드·업로드·활성화 순서, 업로드 실패/잘못된 결과의 활성화 차단, 두 대상 이름 보호, 활성화 실패의 불확실성 보고를 시험한다. 로컬 시험 통과와 실제 양쪽 배포·운영 확인은 구분하며, 실행 결과를 이 문서에 누적하지 않는다.
