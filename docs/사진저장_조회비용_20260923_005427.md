# 사진 저장과 조회 비용 참고

2026-09-23 운영 관리 화면·이번 D1 메타데이터 조회·현재 소스와 공식 요금표를 확인한 읽기 전용 설명이다. 요금제·정책·기능·운영 콘텐츠를 변경하지 않았다. 금액은 USD이며 아래 예시는 세금·환율을 제외한 단순 추정이다.

## 지금은 얼마를 사용하고 있나

현재 Workers는 Free, 사진 저장소는 R2 Standard다. 계정 전체 R2 사용량은 6.12GB이며 이번 청구 기간(2026-08-25~09-25)의 화면상 청구 대상 금액은 $0이다. Class A 작업은 약 8.43천 회, Class B 작업은 약 116.77천 회로 표시됐다. 이는 조회 시점의 누계이며 최종 청구서가 아니다.

| 저장소 구분 | 현재 크기 | 해석 |
|---|---:|---|
| 운영 native | 약 1.43GB | 약 2.75천 객체. 이관 자료도 포함하므로 신규 업로드 사진 수가 아니다. |
| 운영 public | 약 2.35GB | 이관 공개 자료를 포함한다. |
| 시험 public | 약 2.35GB | 시험용 자료도 같은 계정 저장 요금에 합산된다. |

개별 표시값을 반올림해 더하면 전체 표시값과 약간 다를 수 있다. 무료 용량은 저장소마다 따로 주어지는 것이 아니라 계정에서 합산된다.

## 업로드하면 원본을 그대로 저장하나

현재 블로그는 브라우저가 업로드 요청으로 전달한 파일의 바이트를 그대로 R2에 저장한다. 서버에서 사진 크기 축소·압축·화질 변환을 하지 않는다. 따라서 사진 파일 하나가 10MB라면 저장 공간도 대략 10MB가 늘어난다. 휴대폰이나 브라우저가 보내기 전에 파일을 바꿨는지는 별개다.

D1에는 사진 파일 자체 대신 연결 정보 등 메타데이터를 저장한다. 현재 파일당 한도는 25MiB(26,214,400바이트)이며, 편집기의 표시 너비 조절은 CSS 표현을 바꾸므로 저장 파일의 크기를 줄이지 않는다.

이번 D1 조회에서 확인한 최근 업로드 기록은 다음과 같다. **업로드 기록 수이며 현재 첨부 수나 서로 다른 사진 수를 뜻하지 않는다.**

| 글 번호 | 업로드 기록 | 합계 | 파일 크기 참고 |
|---|---:|---:|---|
| #599 | 2개 | 12,284,376바이트 | 각 6,142,188바이트 |
| #600 | 9개 | 93,636,315바이트 | 최소 8,642,354·최대 14,718,822바이트, 평균 약 10.40MB |
| #601 | 3개 | 493,302바이트 | 평균 약 0.16MB |

사용자가 보고 있는 #600의 이번 업로드 기록은 9개·약 93.6MB로, 사진 하나 평균 약 10.4MB다. 운영 공개 본문 DOM에서도 사진 9개를 확인했지만 개별 파일 경로까지 대조한 것은 아니므로 업로드 9개가 현재 사진과 각각 동일하다고 단정하지 않는다. 아래 비용 예시는 계산을 쉽게 하려고 사진당 10MB를 사용한다.

## 사진이 늘면 저장 요금은

R2 Standard 무료분은 매월 저장 10GB-month, Class A 100만 회, Class B 1,000만 회다. 초과 단가는 저장 $0.015/GB-month, A $4.50/100만 회, B $0.36/100만 회이며 인터넷 전송량 자체의 요금은 없다. 저장·작업량의 과금 단위는 올림 계산한다. [Cloudflare R2 공식 요금](https://developers.cloudflare.com/r2/pricing/)

현재 6.12GB가 한 달 내내 유지되고 **평균 10MB 사진**을 추가해 한 달 내내 보관한다고 가정한 R2 저장료 예시다. 작업 요청 비용은 포함하지 않았다.

| 추가 사진 | 계정 전체 저장량 | 월 저장료 추정 |
|---:|---:|---:|
| 1,000장 | 16.12GB | 약 $0.11 |
| 10,000장 | 106.12GB | 약 $1.46 |
| 20,000장 | 206.12GB | 약 $2.96 |

현재 무료 저장량 여유는 약 3.88GB, 10MB 사진 기준 약 388장이다. 실제 저장 요금은 월간 평균 보관량에 따라 달라지므로 월말에 추가한 파일은 한 달 내내 저장한 예시보다 적게 계산된다.

## 열람이 많아지면

현재 native 사진 응답은 `no-store`이고 별도 Cache API를 쓰지 않는다. 사진 GET마다 Worker를 거쳐 D1에서 연결 정보를 조회하고 R2에서 파일을 읽는다. 따라서 사진이 많은 글은 열람 한 번에 여러 요청이 발생한다.

대략 본문 요청 1회 + 관리자 세션 확인 약 1회 + 사진 N회 + 기타 정적 요청이다. 정적 요청도 현재 Worker를 먼저 거치는 구성이다. 조회수 기록은 본문 요청 안에서 D1에 처리하므로 별도의 HTTP 요청을 추가하지 않는다.

- **지금 먼저 고려할 한도는 Workers Free의 계정 전체 하루 100,000요청이다.** 이를 넘으면 요청 오류가 발생하며 자동으로 유료 전환되지는 않는다. 사진 10장이 있는 글에 본문·세션 요청을 합쳐 12회만 잡으면 다른 트래픽 전에도 하루 약 8,300회 열람 정도다. 정적 파일·다른 글·관리자·계정 내 다른 서비스 요청을 빼지 않은 단순 상한 계산이며 보장 방문자 수가 아니다. [Workers 일일 요청 제한](https://developers.cloudflare.com/workers/platform/limits/#daily-requests)
- D1 Free에는 하루 읽은 행 500만 개·쓴 행 10만 개·저장 5GB 제한이 있다. SQL 호출 한 번이 읽거나 쓰는 행 수는 쿼리에 따라 다르므로 SQL 요청 수와 행 수를 같게 계산하면 안 된다. [D1 공식 요금](https://developers.cloudflare.com/d1/platform/pricing/)
- R2 사진 GET만 계산하면 월 100만 회와 1,000만 회는 무료분 안이고 2,000만 회는 약 $3.60이다. 이는 R2의 Class B 요청만의 예시이며 다른 Class B 작업도 합산된다. 현재 Workers Free의 일일 한도는 별도로 적용되므로 이 금액만으로 해당 트래픽을 처리할 수 있다고 보장하지 않는다. [R2 공식 요금](https://developers.cloudflare.com/r2/pricing/)

향후 Workers Paid를 선택하면 최소 월 $5에 요청 1,000만 회와 CPU 시간 3,000만 ms가 포함되고, 초과 요청은 $0.30/100만 회, 초과 CPU는 $0.02/100만 ms다. R2·D1 등 별도 제품의 사용 요금까지 모두 포함하는 정액제는 아니다. 현재 유료 전환은 하지 않았다. [Workers 공식 요금](https://developers.cloudflare.com/workers/platform/pricing/)

현재 수준에서는 사진 원본 저장량보다 사진별로 발생하는 요청과 무료 일일 한도가 먼저 중요해질 수 있다. 압축·리사이즈·캐시 개선이나 요금제 변경은 이번 설명에 포함하지 않았다.
